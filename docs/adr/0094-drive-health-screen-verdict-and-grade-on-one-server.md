# ADR-0094: Drive health on one server: a screen, a verdict from a write pass, and a grade

## Metadata
- Author: Aleksi Ursin / MCX (with Väinämöinen)
- Date: 2026-10-20
- Status: Proposed. The Grade C line below is a default that waits for the operator's confirmation. Adds the tool category `hardware` with the unit `drives` ([ADR-0015](0015-tool-units-one-skill-per-tool.md)), a rule file for the category, and block patterns in the delete guard.

## Context
The operator asked for lightweight drive diagnostics for a basic single server: smartctl testing, the rules on pending sectors, qualification of drives with grades A, B, C and a bin, coloured table reports, and telemetry kept so that verdicts can be saved as lessons. Pikkumies runs as the user and has root only as an optional layer ([ADR-0004](0004-provider-key-and-root-detection.md)); on a dedicated server with root it can read and test the disks.

Engineering facts the design rests on:
- SMART counters (pending, reallocated, uncorrectable) and the health flag are thresholds and counts kept by the drive. Pending sectors are sectors the drive could not read; a write to them lets the drive rewrite or remap them, so pending is often cleared by a write. Reallocated sectors were already remapped. Neither count, nor the flag, says whether the drive still writes and reads back correctly. `smartctl -H` and the drive's long self-test only read.
- `badblocks -n` reads each block, writes test patterns, compares, and writes the original back (badblocks(8)). It skips a block it cannot read, so read errors from it prove nothing about writing that block. `badblocks` refuses only mounted devices (`-f` overrides even that); a disk held by md, LVM or dm-crypt, or one carrying an unassembled array, is not refused by badblocks itself. Its block counter is 32-bit.
- A manual write to a live member of a redundant md array replaces that block's data behind md's back; a later `repair` recomputes parity from the data blocks and keeps the wrong data. md's own `check` reads every block and rewrites an unreadable one from redundancy (kernel md documentation, `sync_action`).
- Device letters change between boots; serials do not, though SATA and SAS print them in different case.

## Options Considered
- **Grade from SMART counters alone.** Rejected: it would call drives bad that a write pass recovers, and good ones that it fails; a count is a screen.
- **Ten verbs** (list, smart, screen, selftest, a badblocks plan and start, status, verdict, history, human output) and a destructive `-w` mode. Rejected for the first cut: listing, screening and history are side effects of one read; a whole-disk `-w` erases the disk.
- **Reuse an existing open-source parser.** The one found is under a licence that is not Apache-2.0-compatible for this repository and labels any reallocated sector a problem; the code here is new.
- **One unit, three verbs, three separate fields (chosen).**

## Decision
- **Unit `hardware/drives`, verbs `smart`, `selftest`, `verify`.** Every verb needs root; without it, it refuses with a hint. The name `drives` is not a tool, toolset, command or bundled skill name in Hermes (checked against Hermes v0.22.2) and not in `Units::RESERVED_NAMES`.
- **Screen, verdict and grade are separate fields.** The screen glyph comes from counters and the health flag and only chooses the next test. A verdict (RECOVERED, HOLD, FAILED, INCOMPLETE) comes only from a write pass the tool saw complete, with SMART samples before and after it, or from the drive's own repeated long-test failures at one LBA, or from reported-uncorrectable growth in service after a pass. While a pass runs, the verdict is HOLD. The verdict table is in the unit README.
- **The array role comes first.** `smart` reports each disk's role (array member, device-mapper holder, mounted, swap, array signature without a running array, other data, blank), and `next` names the write pass that role allows. `verify` runs only on a standalone spinning disk: it refuses an array member (its write pass is the array's own `check` or rebuild), a disk in use, a disk carrying an array or volume signature, and flash.
- **Gates for `verify`:** root, not a VM (`systemd-detect-virt`), the serial equals exactly one listed disk, the device re-resolved from it just before launch, no md array resyncing or checking, rotational, the role above, `--with-data` for any filesystem or partition table and always for `--fix-unreadable` (so the delete guard asks once, [ADR-0020](0020-deletes-need-the-users-approval.md), [ADR-0073](0073-no-questions-no-deferrals-one-reviewed-exception.md)), block size 4096 above 2 TB and 8192 from 16 TB, never `-f`, never a whole-disk `-w`, one pass per disk.
- **Process:** only `smartctl`, `badblocks`, `blkid -p` and `fuser -s` run as root (`sudo -n`, or directly as uid 0). Just before the pass, signatures are probed with `blkid -p` (not the udev cache), the role is checked again, and `fuser -s` refuses a disk any process has open: a VM, an export or a raw-device program would lose its writes to badblocks' read-pattern-restore cycle. The pass is started detached through `flock -n` on the drive's lock file and `sh -c` as the account, with the bad-block list through `head -c` (stopped at 1 MiB, the sign of a drive that dropped), progress and summary in a log, and the exit code in a file. A pass that ends without its summary line is INCOMPLETE and carries the last log line as its reason.
- **Grades come only after a completed write test** (the operator's rule): RECOVERED gives A (everything measured and clean), B (anything on the SMART log below the heavy line, or a counter the drive does not report) or C (heavy wear: reallocated 1000 or more, or uncorrectable 100 or more); FAILED gives BIN. Before a pass a drive is `untested`, however new or clean its self-reported SMART looks; while HOLD or INCOMPLETE it is `undetermined`. A short self-test never earns a letter. A drive read while asleep keeps its last grade, and only a letter that changes on a real reading makes a grade event and a lesson. **Grade C has no earlier definition; its line is a default** (a constant in `DrivesRules.php`), to be confirmed or changed by the operator before this ADR is accepted.
- **History and memory:** per-drive state in `local/drives/<SERIAL>/` (0700; symlinks refused). Numeric samples go to the shared telemetry store when the `telemetry` unit is present; without it the history rule answers `insufficient_history`. When a verdict or grade lands, `smart` emits a `lesson` record with the `save` command; the tool never writes memory itself ([ADR-0018](0018-memory-tool-unit.md)).
- **Guard:** raw `badblocks` with `-w` in any flag cluster (also in a subprocess list), `hdparm --write-sector`, `--security-erase(-enhanced)`, `--security-set-pass`, `--make-bad-sector`, `--trim-sector-ranges` and `--dco-restore`, `blkdiscard`, `nvme format|sanitize|write-zeroes`, `sg_format`, `sg_sanitize`, `mkswap` on a device, output redirected, tee'd or copied (cp, install, qemu-img, ddrescue) onto a disk, a partition, an md, dm, mapper, loop or nbd device or a `/dev/disk/by-*` name, and md `repair` written to `sync_action` (in one command or through tee) are blocked outright; `selftest` is asked as a load. mdadm syntax, `mdadm --action=repair` and `--create` included, is [ADR-0095](0095-md-raid-build-recover-and-tune-through-one-tool.md)'s `GuardDisk.php`, so each command has one owner and its refusal names the right tool (merge, 2026-10-20).
- **Output:** JSON Lines ([ADR-0016](0016-jsonl-is-the-default-output.md)); `--human` prints the table through the shared renderer ([ADR-0017](0017-human-output-option.md)). The colour is the glyph itself (🔴🟠🟡🟢, ⚪ for nothing measured), plain text in every output; no ANSI codes.

## Consequences
- A user with a dedicated server can ask whether a disk is good and get a screen at once, a verdict a day later, and a grade that means something, without the agent calling a recoverable drive dead.
- Array members are never written by this tool; the array's own scrub or rebuild is named instead. Automating re-add, scrub or repair is out of scope.
- The SMART JSON fields for NVMe self-tests and some SAS logs were written from the smartmontools 7 output format, not from a device run in this repository; fixtures cover the shapes the parser reads.
- Follow-ups: the operator's confirmation of Grade C; scheduled collection and alarms, if ever wanted, are separate decisions.

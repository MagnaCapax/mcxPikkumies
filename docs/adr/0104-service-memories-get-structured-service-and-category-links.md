# ADR-0104: Service memories get structured `service` and `categories` links, not a body-text convention

## Metadata
- Author: Väinämöinen (design draft for Aleksi Ursin / MCX review)
- Date: 2026-10-21
- Status: Proposed. Amends [ADR-0084](0084-services-list-and-moving-torrents-between-boxes.md)'s Memory decision and `tools/seedbox/services/skill.md` step 7. Builds on [ADR-0018](0018-memory-tool-unit.md) (lessons/reference/research, frontmatter), [ADR-0060](0060-links-and-the-link-graph.md) (no stored link index — read the files), [ADR-0081](0081-tool-linked-memories-and-an-agent-facing-soft-confirm.md) (`--tool` frontmatter links, `Units::frontmatter`).

## Context
The operator's request of 2026-10-20 (session scratchpad, verbatim): services carry tags for purpose ("seedbox, backup, webhosting, dedicated, workstation, nas, laptop..., multiple allowed") plus a notes field, and "make sure memory has categories etc. for this" (Pikkumies memory categories per service).

What is actually shipped on main:
- `tools/seedbox/services/skill.md` step 7 already tells the agent: "Save what you learn about a box with the memory tool: `--topic services` (a lesson) or `--kind reference` (a fact sheet), and put these two lines at the top of the text: `service: <nick>` and `tags: <its tags>`." — a free-text body convention, written in a prompt.
- `tools/memory/pikkumies/Lessons.php::save` has no `--service` or `--tags` option. Its frontmatter is only `date`, `topic`, `sources`, and (if `--tool` is given) `tools`. The two lines skill.md asks for are plain body text: never validated, never structured, and the agent can misspell a nick or invent a tag that is not one of the box's own.
- `ServicesList::memories($nick, $memoryDir)` (what `services show <nick>` calls) reads only `service: <nick>` — it never reads `tags:` at all — via a regex over the first 64 KiB of files matched by exactly two globs: `memory/lessons/services/*.md` and `memory/reference/*.md`. A lesson correctly about a box but filed under a more fitting topic (e.g. `torrent-clients`, or the provider's own name) is invisible to `show <nick>`, and `memory/research/<kind>` (the third kind `save --kind research` already supports, ADR-0018) is never scanned either.
- So "categories" for services memory exist only as an instruction the code never backs — exactly the gap the operator flagged. `lib/Units.php::frontmatter($text)` already parses a file's `---` header into `[$meta, $body]` (used today by `MemoryCheckTargets::links` to read `tools`), the one reusable primitive this ADR needs.
- `Services::normalize` already validates a tag with `Services::NICK_RE` (lowercase letters, digits, `_`, `-`, ≤32) — the same pattern `Services::nick()` uses for a service name. Reusing it avoids a second vocabulary or a second regex.

## Options Considered
- **Teach `ServicesList::memories` to also regex `tags:`, leave `save` untouched.** Smaller diff, but the lines stay free text: unvalidated, never auto-filled from the service's real tags (so they drift), and still invisible outside the two hardcoded directories. Rejected as not actually fixing the gap.
- **A new, separate "memory category" vocabulary (e.g. access / incident / capability / support).** Rejected: it duplicates a concept the services list already owns (purpose tags) and the operator's own wording ties "categories" directly to the tags just described in the same sentence — a second taxonomy is a DRY violation with no requirement behind it.
- **A stored index mapping memory files to services/tags.** ADR-0060 and ADR-0081 already rejected a stored link index for staleness and locking; the same reasoning applies to a services-memory index. Rejected.
- **Structured frontmatter (`service`, `categories`) written by `save` itself, auto-filled from the named service's current tags, read with the existing `Units::frontmatter` parser across every topic and kind; the old two-directory body-text regex kept as a fallback for files already on disk.** Chosen.

## Decision
- **`Lessons::save` gains `--service "<nick[,nick...]>"` and `--tags "<t,t...>"`.** Each nick is checked with `Services::nick()`'s format (existence in `services.jsonl` is not required — a memory may predate `setup`, or outlive a `services remove`, and ADR-0084's `remove` already tells the user the box's key is gone while its memories are not). Each tag is checked with the same `Services::NICK_RE` a service's own tag already uses. When `--service` is given and `--tags` is not, `save` reads each named nick's *current* tags from `Services::all()` (only the ones that still exist) and unions them as `categories` — the memory inherits the box's own words, never a second typed-by-hand vocabulary. `--tags` always adds to that union — it only adds categories, it never removes one of the service's own tags; it is how a memory gets categories when its service is not in the list (not yet set up, or removed), where there are no current tags to inherit. Both are written to frontmatter, same style as `tools`: `service: ["nick1","nick2"]` and `categories: ["seedbox","backup"]`, omitted when empty.
- **`ServicesList::memories($nick, $memoryDir)` reads frontmatter first.** It globs `lessons/*/*.md`, `reference/*.md` and `research/*.md` (every topic and kind `save` can produce, not only the `services` topic), parses each file's head with `Units::frontmatter` (reused, not reimplemented), and keeps a file whose `service` array (`json_decode`d, same convention `tools` already uses) contains `$nick`. For a file with no `service` frontmatter, or one whose `service` value is not a JSON array, it falls back to today's exact regex over today's exact two directories (`lessons/services/*.md`, `reference/*.md`) — every memory already on disk keeps being found exactly as it is today; memory files are append-only, so their original frontmatter cannot be rewritten by this change.
- **`show <nick>` carries `categories` on each returned memory** (from frontmatter when present, `null` for a body-text-convention file). No new filter verb: the memory unit's `search` already scores a file's whole text including its frontmatter (`lib/TextSearch.php`), so `search nas` finds memories categorised `nas`, and `services list --tag nas` lists the boxes themselves — one vocabulary, existing listings.
- **`skill.md` step 7 is rewritten** to say `--service <nick>` (and `--tags` to add categories beyond that box's current tags) on the `save` command line itself; the two-body-text-line instruction is deleted, since the code now backs the flag instead of a prompt asking the agent to type it correctly by hand.

## Consequences
- A service's memories stay findable wherever they are naturally filed, and inherit that service's own purpose tags without the agent re-typing them, so they cannot drift from the service's own words at save time. They do **not** retroactively follow later tag changes (`services edit <nick> --add-tag x` does not relabel memories saved before it) — consistent with "memory files are only appended to" (ADR-0018); a memory's categories are a snapshot of what the box was tagged when it was learned.
- Every memory file written before this ADR keeps working exactly as today, through the unchanged fallback path; nothing is migrated and nothing needs to be, since memory is append-only.
- One more optional flag on an existing verb, one more reused regex (`Services::NICK_RE`), one more reused parser (`Units::frontmatter`) — no new vocabulary, no new verb, no stored index, no new file format.
- `--tags` on `save` and `--tags` on `services add` must stay the same string shape (lowercase, `_`/`-`, ≤32) or the two listings silently stop matching each other; this ADR ties them to the one constant (`Services::NICK_RE`) specifically so they cannot drift apart in code even if someone forgets to check the ADR text.
- Tests: `tests/LessonsServiceTagsTest.php` (frontmatter written, auto-fill from `Services::all()`, `--tags` extending that union, invalid nick/tag format rejected, omitted-when-empty), `tests/ServicesListMemoriesTest.php` (frontmatter match across `lessons/*`, `reference/`, `research/`; old-file fallback unchanged; a removed service's old memories still listed), plus `tests/DocTiersEdgeTest.php` (the real CLI, through `Cli::run`'s option whitelist, and `search` matching a memory by its `categories` frontmatter).

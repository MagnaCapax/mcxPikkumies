# ADR-0068: SSH connections need a stated intent, and the person's allow and deny lists decide where

## Metadata
- Author: Aleksi Ursin / MCX (with Väinämöinen)
- Date: 2026-10-19
- Status: Accepted. Amends [ADR-0020](0020-deletes-need-the-users-approval.md) (a new question class, `rule_key` `pikkumies-ssh:`), [ADR-0059](0059-settings-tiers-free-asked-and-the-persons-own.md) (three settings, and a list change that adds and removes takes the stricter tier) and [ADR-0049](0049-backup-remote-over-ssh.md) (the deny list applies inside `backup remote`).

## Context
The request of 2026-10-19: "We need hook for SSH connection attempts, requiring the intent IF NOT ALREADY DONE, but we also need blacklist/whitelist options for people to control where it can access ... and document it too docs/".

What was found:
- Nothing judged SSH connections, asked for a reason or kept host lists. `backup remote` reaches one machine over SSH with its own restricted key (ADR-0049); guard-destructive asks about `rsync --delete` but not about where a command connects.
- Hook units run in name order, each in its own process; two approves become one question, blocked when together they pass 350 characters ([ADR-0054](0054-tool-hooks-and-local-hooks.md)). Hermes' approval prompt is answered by the person, never the model, and refused in cron and one-shot runs (ADR-0020); at `PIKKUMIES_DEPTH` 2 or more a question becomes a block.
- Settings already have tiers, and the config-change hook builds the keys it asks about from `ConfigureTiers::RULES` (ADR-0059). Its `list` rule returned the adding tier whenever anything was added, so replacing `[a]` with `[b]` counted as adding: on a deny list that would drop an entry freely.
- `ssh -G` runs `Match exec` commands from the user's config (checked with OpenSSH 10.0p2), so a hook must not ask ssh where a name goes. ssh reads options after the destination (`ssh allowed -o HostName=evil` goes to evil), and the set of option letters changes between versions.
- The agent runs as the user and can edit `local/config.php`: anything enforced belongs to the OS or the other machine (AGENTS.md).

## Options Considered
- **Resolve hosts with `ssh -G`.** Exact, but it runs commands from a config the agent can write, inside the hook. Rejected.
- **A separate intent verb or tool.** A second mechanism the agent can call or skip; the reason belongs with the command it explains, where the command log already keeps it. Rejected.
- **A PATH shim for ssh.** Bypassed by `/usr/bin/ssh`, and it would change what the user's own shell runs. Rejected.
- **Deny rules in `~/.ssh/config` only.** The agent writes that file, and it covers only ssh, not the other programs. Rejected as the mechanism; writes to it are asked instead.
- **Hermes' command allowlist.** Matches whole commands, not hosts. Rejected.
- **A rule inside guard-destructive.** Its first approve would hide the other reason, and the file is already over twice the size target. Rejected: a unit of its own ([ADR-0030](0030-hooks-as-units-run-by-one-orchestrator.md)).
- **`rule_key` per host.** One "always" answer would become a second, hidden allow list. Rejected: the key is the command.
- **Parse the command in PHP, refuse what cannot be read for certain.** Chosen.

## Decision
- **A hook unit** `hooks/guard/ssh-connect/` (`pre_tool_call`, fails closed, 5 s). It reads `terminal` commands and `process_manage` input: ssh, autossh, mosh, sftp, scp, rsync, sshfs, ssh-copy-id, ssh-keyscan and git with an SSH remote, at command position (after `;`, `&&`, a pipe, `$(`, keywords, assignments and the wrappers sudo, env, timeout, nice, nohup, xargs, sshpass and the like), inside `sh -c`, `su -c`, `eval` and `watch`, and anywhere in text a shell reads from stdin. OpenSSH programs use OpenSSH 10.0's option letters exactly; another letter is unreadable, so an older or newer ssh fails safe. Names of a connection: the host typed, `-o HostName` (`%h` filled in), every `-J`/ProxyJump/`-W` hop, the ssh hop of a ProxyCommand, and the hosts of a remote command and RemoteCommand, read again. Names are normalised (lowercase, trailing dot, IPv6 in one form, an IPv4-mapped address as IPv4). Not SSH: the rsync daemon (`host::`, `rsync://`).
- **Order.** Blocks first: a call or host it cannot read (a variable, substitution, glob or brace in the host, an unknown option, a numeric form other than a dotted quad, a program stored in a variable or alias; a command over 100000 characters); SSH from `execute_code` (and paramiko, asyncssh, fabric); any name on `ssh.deny`; a connection without `# intent: <why>` (at least 8 characters) and none remembered; with `ssh.blockUnknown`, a name not on `ssh.allow` or a route it cannot follow. Then one approve, `rule_key` `pikkumies-ssh:` + the first 16 hex digits of sha1 of the command, naming the hosts, the routes and the reason before the command: names not on the allow list; routes (`-F <file>`, `-S`, ControlPath, a ProxyCommand without an ssh hop, `rsync -e`/`mosh --ssh` naming another program, `GIT_SSH_COMMAND`, `GIT_SSH`, `RSYNC_RSH`, `core.sshCommand`); writes to `~/.ssh/config` or `~/.ssh/config.d/` by the file tools (V4A headers included), a shell or code. A question that is not `HookUnits::approveShown()` is a block, never a cut question, and so is one whose command holds control or direction characters; a trailing intent comment is not shown twice (the reason is shown cleaned). Every name allowed: no opinion.
- **The intent marker** `local/state/ssh-intent/<sha1 of session id NUL host>` (0700/0600, removed after 7 days) holds the reason for a host given in an allowed or asked call, so the agent need not repeat it in that session. It only saves repeating: it never allows, refuses or asks, so forging one gains nothing. Written only for a session id matching `^[A-Za-z0-9._-]{1,128}$`. The reason is cleaned (controls, bidi and zero-width characters removed, whitespace collapsed, 200 characters) wherever it is shown.
- **Settings** (amends ADR-0059), read with `lib/SshLists.php` from `Config::fileConfig()`, without the `PIKKUMIES_CONFIG` overlay: `ssh.allow` and `ssh.deny` (type `hosts`: lowercase names, addresses, `*` and `?`, no brackets, so no character classes) and `ssh.blockUnknown`. An entry matches the whole name with fnmatch, never a substring; on the allow list an address pattern matches only an address. The deny list wins; a connection is allowed only when all its names are. Tiers: adding to `ssh.allow` asks, removing is free; adding to `ssh.deny` is free, removing is the person's; `ssh.blockUnknown` on is free, off asks. A `list` change that adds and removes takes the stricter tier (free < approve < person); for `tools.disabled` and `skills.disabled` the result is what it was. Defaults: empty lists, `blockUnknown` off.
- **`backup remote`** (amends ADR-0049): setup refuses a host on `ssh.deny` before any program runs, and every connection (run, list, restore, the commit) refuses a recorded host that is denied now, so a scheduled run that no hook sees is covered. The allow list does not apply there: setup is already asked (`pikkumies-send`) and names the host.
- **Doctrine:** one "Always" line in `doctrine/safety.md` tells the agent to end SSH commands with the intent line.

## Consequences
- A connection is explained in the command log and, for unlisted hosts, in the question; the person controls where the agent connects with two lists and one switch, changed through the configure tool or by hand.
- A safety prompt, not security (AGENTS.md). Out of its sight: a script or program that connects by itself (`./sync.sh`, `make deploy`, ansible, pdsh); `git push` to a remote stored in the repository; an alias or function from an earlier call or `~/.bashrc`; an `Include` in `~/.ssh/config` pointing outside `~/.ssh`; a name that resolves to a denied address (deny is by name; strict mode is the answer); forwards (`-L`, `-R`, `-D`) through an allowed host; raw TCP; a mid-session switch of Hermes to its ssh terminal backend (config.yaml is rewritten at the next start); the person's own commands; an edit of `local/config.php` the config-change hook cannot see (ADR-0059). The limit that holds is on the other machine: `from=`, `restrict` and `command=` in its `authorized_keys`, as backups already do.
- False refusals the agent can fix: a host written through a variable, a here-document line with an unpaired quote in a command that names an SSH program, `scp "$F" host:` (the operand could be a host). Each refusal says to write the host literally. False matches only ask: a command that names `~/.ssh/config` and also redirects (`cat ~/.ssh/config > x`).
- Scheduled Hermes jobs that connect to hosts not on the allow list are refused, because nobody answers there: put those hosts on `ssh.allow`. An unknown host together with another question (`rsync --delete`) is usually over 350 characters and refused naming both checks; allowing the host leaves only the other question.
- One more PHP start per tool call that names an SSH program, git or a related word; others exit after one regex (not measured).
- Writes to `~/.ssh/authorized_keys` (inbound access) are not asked by any check; that is a separate subject.
- Tests: `tests/SshCommandTest.php` (the reader, row by row), `tests/SshConnectHookTest.php` (the hook in a throwaway tree), `tests/SshListsTest.php`, rows in `ConfigureTiersTest`, `ConfigureChangeTest`, `ConfigChangeHookTest`, `HookMergeTest`, `BackupRemoteTest` and `BackupRemoteRunTest`.

# ADR-0093: A scratch folder per session, and a tidy Pikkumies tree

## Metadata
- Author: Aleksi Ursin / MCX (with Väinämöinen)
- Date: 2026-10-20
- Status: Accepted. Adds the hook units `guard/litter-check` (`pre_tool_call`) and `system/scratch-dir` (`pre_llm_call`) ([ADR-0030](0030-hooks-as-units-run-by-one-orchestrator.md)), `lib/Scratch.php`, `lib/TreeLitter.php`, one line in `doctrine/doctrine.md`, one entry in `doctrine/antipatterns.md` ([ADR-0063](0063-common-mistakes-list-changing-data-and-no-python-tools.md)) and one `pikkumies doctor` line. The number is a placeholder until it is merged.

## Context
The operator asked on 2026-10-20 for a garbage-collection and anti-garbage rule with hooks, as the sysadmin agent has: hard gates on creating new folders under the Pikkumies directory, in three layers, with writes there only where Pikkumies fetches its own tools and keeps its state; temporary files in /tmp under a long folder name, told to the agent at session start in a cheap way; and the same shame for scratch left in a working directory. The trigger: an agent wrote scratch screenshots into a relative folder inside a project's working directory, then had to remove them.

What was found:
- The tree is the clone `~/.mcxPikkumies`; `~/pikkumies` links to its `pikkumies/` ([ADR-0001](0001-layout-install-and-update.md)). Everything the user or the agent writes belongs in `pikkumies/local/` or the lessons in `pikkumies/memory/` (AGENTS.md "State is never tracked"). What Pikkumies downloads for its tools lands in `local/` too: Hermes' Python and skills under `local/hermes/` ([ADR-0033](0033-vanilla-hermes-git-checkout-updated-separately.md)), the speech model under `local/whisper/`, the browser under `local/browse/`. The rest (the Hermes checkout `pikkumies/hermes/`, `include/`, the generated indexes) is written by the installer and the updater, which run as programs, never as the agent's tool calls. `.gitignore` already names every one of these, so "tracked or ignored" is the expected tree, kept up to date by the repository itself.
- The updater only fast-forwards and stops on local changes ([ADR-0001](0001-layout-install-and-update.md)); a stray file in the tree can also block a later update that adds the same path.
- PMSS gives every account the same `/tmp`: no `pam_namespace` and no `PrivateTmp` in the PMSS code; with `PMSS_HARDEN_TMP_TMPFS=1` (off by default) it is a 2 GB tmpfs mounted `noexec,nosuid,nodev` (`scripts/lib/update/services/mountHardening.php`, `docs/update.md`). A folder there has to be made the way a shared directory needs (CWE-377, CWE-379).
- Hooks see `session_id`; tools do not, and a hook cannot change the environment of the terminal tool. A per-session folder can only be told to the agent in its context, not exported.
- A hook's block reaches the agent only as `message` (`lib/HookAnswers.php`): the "this refusal is the answer" text of [ADR-0065](0065-a-tool-refusal-carries-a-stop-field.md) has to be in that text.
- The shell-word splitter of the ssh-connect hook (`SshWords`) already reads quotes, substitutions and redirections; it dropped redirection targets. `SshExpansion` used `SshUnreadable` without loading it, so publish-check failed closed on every `git push` with a variable in it.

## Options Considered
- **Doctrine only.** Read once per session, far from the moment of the write; it did not stop the trigger case.
- **Make the tree read-only to the account.** Breaks `pikkumies update` and the installer, which run as the account.
- **A guard rule inside guard-destructive.** One more rule in a 360-line file with its own subject; a unit of its own keeps one subject per unit, as publish-check did.
- **Scratch under `local/tmp/`.** Inside the tree and on the quota-bound home; the operator asked for /tmp.
- **Three layers, each catching what the others miss (chosen).**

## Decision
- **Layer 1, `guard/litter-check` (`pre_tool_call`, fails closed, 3 s).** A terminal command, or a `write_file` or `patch` call, that would create a file or folder whose real path is inside the clone but outside `pikkumies/local/` and `pikkumies/memory/` is blocked. Targets: output redirections and the programs that create files (`mkdir`, `touch`, `tee`, `truncate`, `dd`, `cp`, `mv`, `install`, `ln`, `rsync`, `git clone`/`init`, `curl`, `wget`, `tar`, `unzip`, `zip`, `mktemp`), words read by `SshWords`, which now also returns redirection targets. The text after `sh -c`/`bash -c` is read again; wrappers (`sudo -u x`, `env -u X`, `timeout -s SIG`, `busybox`) are skipped with their option values; here-document bodies are not read as commands (W-5, W-6). A relative path is read from a `cd` in the same command or the call's `workdir` (terminal), or the payload's `cwd` (file tools, as GuardLocal reads them). Every existing part of the path goes through `realpath`, a dangling symlink to where it points, so a link does not get around it; a glob, an expansion or an extracted archive counts by its folder, and a target that starts with an expansion (`"$LOG"`, `"$(mktemp -d)/x"`) is not placed at all. Only new entries count: changing an existing file is config-change's and guard-destructive's business. The message names the session's scratch folder and says the refusal is the answer.
- **Layer 2, doctrine.** One line in the Memory section of `doctrine.md` (reaches SOUL.md): temporary files go in the session's scratch folder, never in a working directory or under `~/pikkumies`; small files only, large ones in the home folder. One common-mistakes entry, `[litter-in-the-tree]`.
- **Layer 3, the tree check.** `TreeLitter::stray()` runs `git --no-optional-locks -c core.fsmonitor=false -C <clone> ls-files -z --others --exclude-standard --directory` (read-only, 2 s) and lists what is neither tracked nor ignored. Not `git status`: the agent can write `.git/config`, and status would run its `core.fsmonitor` command, and the clean filter of every stat-dirty tracked file even with fsmonitor off, inside the hook with Hermes' environment (security review W-1). `system/scratch-dir` names up to five such entries when a session starts; `pikkumies doctor` prints the same line. It never deletes.
- **The scratch folder (`lib/Scratch.php`).** `/tmp/pk-<uid>/<32 hex>`: the base must be a real directory owned by root or the account, sticky when others can write it; the account's parent `pk-<uid>` is made 0700, or when it exists must be a real directory owned by the account with no group or other bits (one another account made is refused, never used), so no other account can take a name a session used before (W-3); each session folder is made with one `mkdir` under umask 077 (it fails on any existing name), then checked with `lstat` the same way. It is for small files only: the doctrine line and the announce line send downloads, archives, builds and anything large to the home folder, since `/tmp` is shared and may be a 2 GB tmpfs (W-4). The session's folder is recorded in `local/state/scratch/<sha1 of the session id>`. `system/scratch-dir` looks it up every turn and says nothing while it exists; a new folder (first turn, or after a reboot emptied `/tmp`) is named in one line.
- **Clean-up.** When a folder is made, `Scratch::prune()` removes this account's folders untouched for 7 days (each turn touches the live one) and their records: only names of the account's pattern, checked with `lstat` for owner and type; symlinks are unlinked, never followed; a folder with a mount point at or below it in `/proc/self/mountinfo` (which also shows a bind mount from the same filesystem, W-2), or a different device below, is left and counted as failed, and so is every old folder when mountinfo cannot be read. Only the counts go to the hook log.
- `SshExpansion` loads `SshUnreadable` itself.

## Consequences
- What each layer catches that the others miss: the guard stops the write before it happens, through symlinks and relative paths, but cannot see a path built in a variable it cannot read, a `cd` from an earlier call, code run by `execute_code`, or a program that writes by itself (a build, a package manager, a script). The doctrine line reaches the agent before it plans any write, including in working directories outside the tree, where the guard does not look. The tree check sees the result on disk whatever made it, but only afterwards and only in the clone.
- The `pre_tool_call` entry grows by 3 s and `pre_llm_call` by 3 s of timeout (CoreTest fixtures).
- A false refusal is possible when a command writes through a variable while its `workdir` is in the tree; the message names where to write instead.
- Developing Pikkumies happens in a separate clone, never in the installed tree. A safety prompt for the agent's own mistakes, not a security boundary (AGENTS.md).

# ADR-0087: Tool, skill and verb usage counts, kept on this machine

## Metadata
- Author: Aleksi Ursin / MCX (with Väinämöinen)
- Date: 2026-10-20
- Status: Accepted. Extends [ADR-0086](0086-local-only-telemetry-history-for-diagnostics-and-health-runs.md) (the local telemetry store), [ADR-0041](0041-memory-metrics-save-reminder-and-wide-search.md) (`privacy.perfLogging`) and [ADR-0044](0044-every-shell-command-is-logged.md) (the `post_tool_call` observer pattern `hooks/trace/command-log` already follows). Amended 2026-10-20 after a security review (report section F-TEL): (F1, CWE-532) the first lowercase word after a unit path was recorded as the verb whether or not it actually was one (`php <unit> hunter2passw0rd` recorded the field `hunter2passw0rd`); (F2, CWE-41) a relative unit path was resolved against the hook process's own cwd rather than the tool call's, so a look-alike run from another directory could be miscounted as the real unit, the documented `~/pikkumies/...` form was never counted at all (no `~` expansion), and a command that only *mentioned* a unit (`echo 'php ... show'`) was counted as running it; (F4, CWE-200) `serve`'s `series`/`list` allow-list for this tool made no exception for `usage-*`, so a linked box could read what tools, skills and verbs ran on this machine, not only a service account's diagnostic history. Fixed: the verb is kept only when it is in the unit's own USAGE.md verbs table, else `other`; a relative path resolves against the payload's own `cwd` (never matched with none given), a leading `~/` against this process's HOME, and only a `php` call that starts the command or follows `&&`/`;`/`|` is read at all; `TelemetryLog::series()`/`listSources()` hide every `usage-*` source when `PIKKUMIES_SERVE=1` (set by `serve.php` for every tool it runs), exactly as if that source did not exist. (F3, CWE-400, growth) was reviewed and found already correct: kept forever is the operator's own choice, and the per-file size cap already bounds the worst case.

## Context
The operator's request, verbatim: "We should log all the skills and tools used for telemetry inside the system, basicly collect stats how many times a skill was invoked, a tool was invoked, if we are nto already doign that."

What was found:
- Hermes already counts this, inside itself: `/insights` (`agent/insights.py` `_get_tool_usage`, `_get_skill_usage`) reads `state.db` for per-tool call counts and per-skill (`skill_view`) loads. Pikkumies keeps sessions forever by default, so the data exists. But every Pikkumies tool unit runs as `php <root>/tools/<cat>/<tool>/<tool>.php <verb>` through the `terminal` tool (`lib/Units.php`), so `/insights` lumps every one of them under "terminal" -- it cannot answer "how many times was `rtorrent stats` run." PHP also cannot read `state.db` on every host, and the schema is Hermes', not Pikkumies' to depend on (the reasoning [ADR-0061](0061-status-line-memories-context-tool-calls-code-lines.md) already used to reject that database for the status line).
- `hooks/trace/command-log` already sees every `terminal` call (ADR-0044), but not `skill_view`, so it only answers half the question, and it logs the command, not a count.
- `post_tool_call` fires after every tool call, Hermes tool or Pikkumies unit alike, carrying `tool_name`, `tool_input` and `extra.result` -- the same signal `/insights` itself reads.
- ADR-0086 already built the one thing this needed: a local-only history, gated by `privacy.perfLogging`, that any observer can write a tiny record into.

## Options Considered
- **Point users at Hermes' `/insights`.** Rejected: misses every Pikkumies unit (they are all "terminal"), and is not JSON the agent can read.
- **A reader over the command log only.** Rejected: it never sees `skill_view`, so it misses skill counts entirely, half of what was asked.
- **A fourth store, via `MetricsLog` (ADR-0041's class).** Rejected: would duplicate ADR-0086's store for no reason; `MetricsLog`'s monthly-per-kind shape does not fit an open set of tool/skill/unit names either.
- **A `post_tool_call` observer hook writing into `TelemetryLog`, plus a `telemetry usage` verb (chosen).** No new store, no new setting; the same local-only promise ADR-0086 already made.

## Decision
- **New hook unit**, `pikkumies/hooks/trace/usage-count/` (`post_tool_call`, `failClosed: false`, `timeout: 2`). Every tool call writes source `usage-tool`, field = the Hermes tool name, value 1 (succeeded) or 0 (failed: a non-empty `error`, or for `terminal` a non-zero `exit_code`). A `skill_view` call that names a skill also writes `usage-skill`, field = the skill name. A `terminal` call whose command runs a `*.php` script of this install's own `tools/` tree also writes `usage-u-<tool>`, field = the verb -- the path is resolved with `realpath()` and must land under `Units::toolsDir()`, so a look-alike path elsewhere is never counted. A name is lowercased, "-"/"/" become "_", and anything that still fails `TelemetryLog::FIELD_RE` becomes `other`. Each write is its own try/catch, failing open into `TelemetryLog::noteFailure()`: one source's failure never stops the others or the tool call being counted.
- **`TelemetryLog::counts($source, $days, $localDir = null)`**: field => `[calls, ok, last_ts]` over the window, read a line at a time -- the piece ADR-0086 did not need until now (it has no way to list a source's field names with their counts; `series` needs the field named in advance).
- **Growth exception, scoped and justified.** ADR-0086's per-minute cap (its own security review, row F9c) exists to stop a *diagnostic snapshot* source (`stats` and friends) from being grown faster by a remote `serve` peer calling an allowed verb in a loop than by a local run. A usage-count source is the opposite shape on purpose: many small writes a minute *is* the feature, and none of `usage-tool`, `usage-skill` or `usage-u-<tool>` is ever reachable through `serve` (that hook never runs there). Applying the snapshot-style per-minute throttle to a counter source would silently discard real calls -- undercounting, not safety. `TelemetryLog::record()` therefore takes a `$counter` flag (default `false`, unchanged for every existing caller) that skips the per-minute check only; the per-file size cap still applies to a counter source exactly as it does to everything else, so growth is still bounded, just by a limit that fits what is being measured.
- **`telemetry usage [--days N] [--kind tool|skill|unit] [--human]`** (new verb, `tools/system/telemetry/telemetry.php` + `UsageStats.php`): one record per name (tool/skill) or name+verb (unit), `kind`, `name`, `verb`, `calls`, `ok_pct`, `last` (UTC), sorted by `calls`. `--days` 1-3650, default 30. With `privacy.perfLogging` off: an empty list and a `note` saying so and where to turn it on, never an error. `--human` renders a 10-cell-bar table, the shape memory's `stats --human` already uses.
- **Privacy, unchanged from ADR-0086.** Gated by `privacy.perfLogging` (through `TelemetryLog::record` itself: off writes nothing). `privacy.telemetry` is never read -- it stays reserved for a future external sender (ADR-0032), and nothing built here sends anything. A user-made skill name becomes a field name on this machine, same as any other field; it is never sent, and it is `other` if it does not fit `TelemetryLog::FIELD_RE`.
- **Docs**: this ADR; `hooks/trace/usage-count/README.md`; `tools/system/telemetry/README.md` and `USAGE.md` (the `usage` verb row and a "Usage counts" section); the `privacy.perfLogging` description text everywhere it is shown to the person (`ConfigureSettings.php`, `pikkumies-configure/skill.md` and `USAGE.md`, `Launch.php`'s first-start settings note, `docs/install.md`) now also says it keeps tool, skill and verb usage counts.

## Consequences
- "How many times was X used, and how often did it succeed" is answerable locally, in JSON, for every Hermes tool, every skill and every Pikkumies unit's verb -- without Hermes' own database.
- One more unit process per tool call (`hooks/trace/usage-count`), the same cost class [ADR-0061](0061-status-line-memories-context-tool-calls-code-lines.md) already measured for one hook unit (its own figure: about 25 ms, PHP 8.4). `failClosed: false` and a 2-second timeout mean a slow or broken hook never blocks the call it is counting.
- Files are kept until `telemetry prune` is run by hand, same as every other telemetry source; the per-file size cap bounds a single source's worst case regardless.
- A user-made skill name, or an MCP/plugin tool name, is stored locally as a field name (or `other`); it is never sent, consistent with AGENTS.md's privacy rule.
- Follow-up outside this unit, left to whoever wants it later: surfacing `telemetry usage` output through `pikkumies doctor`, the way memory's own search-metrics line already does.

# ADR-0067: Interval hook units: background checks over the session's records

## Metadata
- Author: Aleksi Ursin / MCX (with Väinämöinen)
- Date: 2026-10-19
- Status: Accepted. Amends [ADR-0030](0030-hooks-as-units-run-by-one-orchestrator.md) (a hook.md field and a unit-only event) and [ADR-0054](0054-tool-hooks-and-local-hooks.md) (local units may not use it). [ADR-0044](0044-every-shell-command-is-logged.md) is unchanged. The one-shot runs of [ADR-0047](0047-halt-guard.md) start no background run at the end of a turn.

## Context
The operator asked on 2026-10-19 for orchestration of synchronous and asynchronous hooks, so that checks can run in the background: one that looks at the agent's tool calls about every minute and judges whether they changed data, one that looks at the user's requests at most once per ten minutes and gives the agent back at most 10k tokens, and checks over the session's transcript every five or ten minutes, fully asynchronous, each with a configurable interval.

Every hook unit so far runs inside a Hermes hook entry, in line with the call or turn, and the turn waits for it ([ADR-0030](0030-hooks-as-units-run-by-one-orchestrator.md)). A check over several minutes of a session needs a different shape: something that sees the session's tool calls, messages and replies, runs at most once per interval, and never makes a turn wait for it. This ADR adds that scheduler. The two checks the request names get ADRs of their own; this one ships none.

Facts this rests on, read in Hermes v0.22.2 (d923a5eb4):
- `post_llm_call` fires once per turn, after the tool loop, with `user_message`, `assistant_response`, `conversation_history` (the turn's messages) and `turn_id` (`agent/turn_finalizer.py`:470). It is in `VALID_HOOKS` and not in `SHELL_UNSUPPORTED_HOOKS` (`hermes_cli/plugins.py`:109-119, 208). `pre_llm_call` gets `conversation_history`, `is_first_turn` and `turn_id` (`agent/turn_context.py`:798-821); `pre_tool_call` and `post_tool_call` get `turn_id`, and `post_tool_call` gets `status`, which is `"blocked"` for a call a hook held (`model_tools.py`:944).
- Hermes refuses a hook event it does not know (`agent/shell_hooks.py`:224), so a new unit-only event can never appear in the generated config.
- A shell hook runs in its own process group and Hermes reads its pipes to the end (`agent/shell_hooks.py`:330, 352). A timed-out hook is killed with all its descendants by parent pid, then its process group (`agent/deadline.py`:422-472). Hooks that finish in time keep detached helpers alive (the comment at `agent/shell_hooks.py`:328).
- User rows Hermes adds itself carry a flag ending in `_synthetic` or `_nudge` (`agent/conversation_compression.py`:2199). A scheduled run's session id starts with `cron_` (`cron/scheduler.py`:2553). `pre_verify` fires only in a turn that edited a file (`agent/turn_stop_gates.py`:52-55).
- Checked here on PHP 8.4: `timeout` started by `exec('... &')` has parent pid 1 and its own process group, and a lock closed without unlocking stays held by a child that inherited it. The test suite repeats the first on every run.

## Options Considered
- **A cron job that sweeps sessions.** A process every minute for every account, whether or not anyone is in a session, and Pikkumies' crontab line runs Hermes' own jobs, not hooks ([ADR-0025](0025-scheduled-jobs-per-minute-tick-under-no-new-privs.md)). Rejected for now; a session no later event revisits is not swept.
- **Run the check inside the hook entry, every N calls.** The turn would wait for a model call of up to 40 seconds. Rejected.
- **A long-running daemon per session.** Against [ADR-0022](0022-pikkumies-is-the-one-command-prompt-routing-and-path-install.md)'s per-invocation design. Rejected.
- **Record each turn in the orchestrator; start a short-lived detached worker per due unit (chosen).**

## Decision
- **The unit.** An interval unit is a shipped hook unit whose `hook.md` says `event: transcript` and adds `every` (seconds, 60 to 3600, the default interval) and, optionally, `wake` (a comma list of the record kinds that make a run worth starting: `user`, `assistant`, `reply`, `tool`, `change`; default any). `failClosed` must be false, `timeout` is 1 to 110 seconds, and `every` must be more than `timeout` + 15, so two runs of one unit never overlap. `transcript` is not in `HookUnits::EVENTS`: no Hermes entry is ever generated for it, no unit of a real event runs it, and a broken unit that declares it still blocks every `pre_tool_call` (ADR-0030). A local unit (`local/hooks/`) declaring it is refused and named: it would read the session's records in the background.
- **Settings.** `hooks.every.<unit name>` overrides one unit's interval (clamped to 60..3600 and above its timeout + 15; 0 turns that unit off); `hooks.async.disabled` turns every interval unit off. The key is the unit's name, not its category path, because the configure tool, its undo log and the config-change hook read keys of letters, digits, dots and dashes. Tiers ([ADR-0059](0059-settings-tiers-free-asked-and-the-persons-own.md)): `hooks.async.disabled` set true is the person's, false is free; for `hooks.every.<name>`, a unit in `guard/` is a safety check (more often is free; less often or 0 is the person's) and any other unit may spend the user's credits (less often or 0 is free; more often asks).
- **Records** (`lib/HookRecords.php`, `lib/HookSpool.php`): while an interval unit is on, the orchestrator appends to `local/state/async/transcript/<sha1 of session_id>.jsonl`:
  - `user` at `pre_llm_call`: the message, at most 4000 characters, with `first_turn`;
  - at `post_llm_call`, the rows of this turn after its user row (the last user row without a Hermes flag whose text ends with `user_message`): each assistant text as `assistant` (at most 1500 characters; the final answer is not repeated) and a user row Hermes added as `user` with `synthetic: true`; then `reply`, the final answer (3000). When the turn's user row cannot be found (compaction), only the reply is kept, with `compacted: true`;
  - `tool` at `post_tool_call`: tool, arguments as JSON (2000), status, error type, error (300), the exit code of a `terminal` call, and `change` (below). A tool's output is never kept.
  Each record has `seq` (the last one + 1, numbered under the file's lock), `ts`, `turn_id` and `scheduled` (the session id starts with `cron_`). Every text is cut to its cap, then goes through `Redact::secrets`; a record whose redaction fails is dropped, never kept unredacted. Past 256 KB the oldest tool records go first, then the oldest of any kind, down to half; the newest record always stays, so numbering never restarts. This is a separate spool of arguments only, beside the command log of ADR-0044, which is unchanged.
- **What changes data** (`lib/ChangeClassify.php`, `lib/ChangeVerbs.php`, `lib/ChangeUnits.php`): `true`, `false` or `"unknown"` per call, from the call alone. `write_file` and `patch` are changes; the read tools and any blocked call are not; `execute_code` and other tools are unknown. A shell command is split into simple commands with `FileopsClassify::words`, which now also returns its `redirects` (an additive key: its words and complex flag are unchanged, pinned by a test). An output redirect into a file (not `/dev/null`, not `>&2`), a write verb (`rm`, `mv`, `cp`, `tee FILE`, `kill`, ...), a write flag of a verb (`sed -i`, `sort -o`, `curl -o`/`-d`/`-X POST`, `find -delete`, `find -exec rm`, ...) or a write subcommand (`git commit`, `systemctl restart`, `apt install`, ...) is a change, after skipping wrappers (`sudo`, `env`, `timeout`, `xargs`, ...; `FileopsClassify::WRAPPERS`). Known read verbs, and pipelines of them, are reads. Shells, interpreters, `eval`, command substitution and verbs in neither list are unknown. A Pikkumies tool unit's call (`tools/<category>/<tool>/<tool>.php <verb>`) is read from its USAGE.md verb table: `no` or `loads` is a read, `yes`, `deletes`, `sends` or anything else a change, a verb not in the table unknown; USAGE.md is read only for such a path. These tables are this check's own; the guards keep theirs.
- **When a unit runs** (`lib/HookAsync.php`): a record of a unit's wake kinds sets that unit's flag for the session (`change` also matches unknown). At `post_tool_call` and `post_llm_call`, after the answer is printed and every lock is released, each unit whose flag is set and whose interval has passed since its last start is started: its stamp is written under the stamp's lock taken without waiting, so two parallel calls never both start it. `pre_llm_call` and `pre_tool_call` start nothing. A one-shot run (`PIKKUMIES_ONESHOT=1`, set for every Hermes process of a one-shot `pikkumies` run) still records at `post_llm_call` but starts nothing there: the process ends after the turn, so a background result could not be shown, and a check judged at the end of the turn would find the run already taken by a worker whose result goes nowhere.
- **The detached start**: `timeout -k 5 <unit timeout + 10> [setpriv --no-new-privs] [nice -n 19] php hooks/worker.php <unit> <sha1> </dev/null >/dev/null 2>&1 &`, every word through `escapeshellarg`; `timeout`, `setpriv` and `nice` are found on PATH. The shell exits at once, so `timeout` is reparented away from the hook and sits in its own process group: Hermes' kill of a timed-out hook does not reach it, and Hermes' read of the hook's pipes is not held open by it. Never `timeout --foreground`, which stays in the hook's group. A shell string, not proc_open's array form, because the product runs on PHP 7.3. Without `timeout` on PATH nothing is started and no stamp is written (logged `async-start-failed`). `nice` only, not the idle I/O class, so a busy disk does not starve the check.
- **The worker** (`hooks/worker.php`) runs only a valid shipped interval unit that is on, for a well-formed session hash. It takes the unit's run lock and one of two worker slots per account, neither waiting; busy, it sets the unit to be tried again 30 seconds later and exits. Holding both, it clears the wake flag, gives the unit on stdin `{"unit", "session" (the sha1), "interval", "now", "first_run", "scheduled", "records" (since its last run, oldest first), "state", "dropped" (when the cap removed some of its records)}`, runs it with its own timeout, and keeps its answer, every key optional: `context` (text for the next turn, at most 4000 characters), `notice` (at most 900; `noticeOn` may only be `change`) with `holdsPerTurn` (1 to 3, default 1), `state` (at most 4096 bytes, given back next time) and `skip` (true: the cursor stays, so the same records come again with the next ones, and the next record of its wake kinds starts it at once). Over a cap, that part is dropped and logged. One line per run goes to the hook log with event `async`.
- **Delivery** (`lib/HookPending.php`): one pending context and one pending notice per unit and session, the newest replacing the older, written through a temporary file and a rename under a lock that delivery takes without waiting. A context is added at the session's next `pre_llm_call`, after Pikkumies' own notes and the hook notes and before local units' text, so the 9000-character cap cuts it before the local-hook failure lines ADR-0054 must show, labelled `Pikkumies <unit> (background check from session records):`. A notice holds the next tool call that may change data (`true` or `"unknown"`) once, as a block whose message is the notice, only when no other unit blocked that call or asked a question the ask policy kept (a dropped question is no opinion, [ADR-0073](0073-no-questions-no-deferrals-one-reviewed-exception.md)), at most `holdsPerTurn` times a turn and never twice within 60 seconds; one still pending at the next `pre_llm_call` is shown there as context, so it is never lost. Delivery checks with `stat` first, never waits for a lock and runs inside a catch, so a fault means no hold, logged as `async-deliver-error`, never a blocked call. Output is advisory: it can hold one call once or add text; it never approves, allows or changes anything. Text a unit passes on is the unit's to flatten and label as untrusted; the orchestrator cannot tell it from the unit's own words.
- **Shared run record** (`lib/HookRun.php`): `HookAsync::due()` only looks; `HookRun::beginRun()` takes the unit's lock and a new stamp, or answers false; `HookRun::endRun()` moves the cursor, saves the state and releases. A synchronous caller of the same unit (a check at the end of a judged turn) uses the same calls, so both share one stamp, one cursor and one state, and neither runs while the other does.
- **Files**: `local/state/async/transcript/<sha1>.jsonl`, `local/state/async/<category>-<name>/<sha1>.{wake,stamp,lock,cursor,state.json,context.json,notice.json,plock,held}`, `local/state/async/slot-{1,2}.lock`; directories 0700, files 0600 (the code sets the umask itself: hooks do not inherit the launcher's). Removed at the next turn once older than 7 days, or than `sessions.retentionDays` when that is shorter; a context or notice removed unshown is logged as `pruned-undelivered`.
- **Visible state**: the hook index shows `interval, every Ns (Ms by default)`; `pikkumies doctor` shows each unit's interval and, from the last day's hook log, its runs, skips, errors, timeouts, holds, texts shown and texts pruned unshown.
- **The agent's own account can edit every file here**: stamps, cursors, flags, spools and pending texts. They feed safety prompts, never an allow ("hooks are safety prompts, not security", AGENTS.md).

## Consequences
- Background checks become one directory each, with the interface above.
- Every `pre_llm_call`, `post_llm_call` and `post_tool_call` while an interval unit is on costs one append and one flag check per unit (milliseconds). `post_llm_call` gets a Hermes entry of 5 seconds while a unit is on, one more PHP start per turn (about 20-30 ms, ADR-0030). With no interval unit shipped or on, nothing changes: no entry, no file.
- At most two workers per account at once, each living at most its timeout + 10 seconds.
- A session that goes quiet is not checked again until its next event, and a run's text waits for the next turn. A scheduled run rotated by compression gets a new session id without the `cron_` prefix and is then not marked scheduled.
- The orchestrator moved its unit runner and hook log into `lib/HookSpawn.php` and `lib/HookLog.php`, unchanged, so the worker uses the same ones.
- Departures from the reviewed plan, with reasons: the per-unit setting is keyed by the unit's name (above); a skipped run does not set its wake flag again, because that would start a worker on every later tool call until the next real record; tool-unit calls are read with `FileopsClassify::words` rather than the search gate's plain-call parser, which answers only "one plain call or not" and refuses every pipeline; `noticeOn: any` was dropped (no unit needs it).

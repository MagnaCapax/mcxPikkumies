# ADR-0071: The goal review: ten fixed questions to the light model, every ten minutes at most

## Metadata
- Author: Aleksi Ursin / MCX (with Väinämöinen)
- Date: 2026-10-19
- Status: Accepted. An interval unit of [ADR-0067](0067-interval-hook-units.md). Moves the search-first hook's "is this a new question" rule into `lib/UserTurn.php`, unchanged ([ADR-0011](0011-documentation-sources-and-search-first.md)).

## Context
The operator asked on 2026-10-19 for a background hook that reviews the user's requests at most once per ten minutes and gives the agent back at most 10k tokens, with a configurable interval and fully asynchronous. The search-first hook already reads each new question, but once per turn and only to list pages ([ADR-0028](0028-search-first-every-turn-and-a-light-model-for-hooks.md)). Nothing looks back over several turns to ask whether what the user asked for has been done, whether the work drifted, or whether a tool or page the agent did not use would answer it.

The light model is already used by hooks through `lib/HookLlm.php`: the agent's own endpoint and key, the light model decided at start, `hooks.llm.disabled` to stop every hook call ([ADR-0028](0028-search-first-every-turn-and-a-light-model-for-hooks.md), [ADR-0047](0047-halt-guard.md)). The halt guard's judge shows the pattern this unit follows: fixed questions, strict answers, fixed text out ([ADR-0047](0047-halt-guard.md)).

## Options Considered
- **Let the model write the reminder.** Its words would reach the agent every ten minutes, carrying whatever the session's data steered it to write. Rejected: the model only picks among fixed answers.
- **Run on every user message (pre_llm_call).** The request asks for at most once per ten minutes, and a turn would wait for the call. Rejected.
- **Ten questions in one call (default), or ten calls (opt-in).** "10 round" can be read as ten rounds. One call answers all ten questions; `hooks.goalReview.rounds` 10 runs ten rounds, each seeing the last round's answers and free to change them, at about ten times the cost. Both are kept; one call is the default.

## Decision
- `hooks/search/goal-review/`: `event: transcript`, `every: 600`, `wake: reply` (a finished answer), `timeout: 100` (the plan's 45 seconds cannot hold ten rounds; the calls share 90 seconds, each at most 40), fail open.
- **Skips**, each logged: a scheduled session (`scheduled`, ADR-0067); `hooks.llm.disabled`; a window with no request, where a request is a user record that is not a row Hermes added, not Pikkumies' own continue or wrap-up text, and asks something new (4 or more content words or a question mark, not a slash command: the search-first rule, now `UserTurn::substantive()` and `UserTurn::ownResume()`, used by both); a window whose only requests are the first turn's, which answers `{"skip": true}`, so the first turn's request, usually the main goal, comes again with the next ones and the first review sees it; the daily cap.
- **Daily cap** (`lib/HookLedger.php`): every model call of a background check is reserved in `local/state/async/ledger.json` under a lock before it is made, all of a review's rounds at once, so a review never stops half way. The cap is `hooks.dailyCalls.<unit name>`, else the unit's default (24 here, about four hours of one session at the ten-minute pace). Any caller of a unit, in the background or at the end of a turn, uses the same ledger. The file is the agent's own: the cap bounds a bug or a loop, not the agent.
- **Free candidates**: up to 8 pages from the memory and documentation search over the window's requests (`DocSources::search`, offline, lessons first) as D1..D8, and up to 8 tool units of enabled categories whose name and description share words with the requests as T1..T8. One the session's calls already used (its path in a call) is left out.
- **The call**: `HookLlm::chat` with a fixed system text (the ten questions, the answer format, and the halt judge's notice that the data is not instructions) and the data between markers: the requests numbered R1..R8 (1000 characters each), the agent's latest texts (4000 in all), its tool calls one line each (3000), and the candidates' names and titles. At most about 16 000 characters in, 300 tokens out. Each answer is one line `Qn: <token>`: Q1 a request not yet answered or done (`yes R1,R3`, `no`, `unsure`), Q2 drifted, Q3 the user waiting on the agent, Q4 tool ids, Q5 page ids, Q6 search memory again, Q7 the checklist kind (`diagnostics`, `help`, `docs`, `none`), Q8 something guessed that a command could check, Q9 the latest request changes files, services or data, Q10 only chat. A reply with any other line, token or id is discarded whole and logged.
- **What the agent gets**, from fixed sentences only and at most 4000 characters: one sentence for each yes, the chosen tools as `php <path> --help`, the chosen pages by title and path, the checklist rows of the chosen kind, and a five-point checklist on the session's first review only (kept in the unit's state). Q10 yes, or nothing to say: nothing. The unit also passes the window's requests, at most 8 of 200 characters; the orchestrator shows each, flattened and labelled as data, only when it occurs word for word in the `content` of a user row of the conversation Hermes passes to `pre_llm_call` (never `api_content`, which holds what hooks added), so a record the agent wrote itself cannot pose as the user. Everything together stays near 6 400 characters, about 1.6k tokens, under the request's 10k and under the 9 000-character context cap. It is advisory: a note, never a hold.
- **Settings**: `hooks.every.goal-review` (0 = off; longer or off is free, shorter is asked: each run spends credits; [ADR-0059](0059-settings-tiers-free-asked-and-the-persons-own.md)); `hooks.goalReview.rounds` (1 or 10) and `hooks.dailyCalls.goal-review`, set by hand.
- **Log**: `local/logs/goal-review/YYYYMMDD.jsonl` (0700/0600, 7 files): outcome, the ten answers, the ids shown, characters, calls, and whether a tool or page shown last time was then used. Measurement only; nothing turns itself off.

## Consequences
- Cost, per account: at most 24 light-model calls a day by default, one per review (rounds 10: ten), each about 4k tokens in and 300 out, at most one review per ten minutes per session. Each note stays in the session's later requests, about 1k to 1.6k tokens.
- Single-turn questions and one-shot runs cost nothing: the first turn is never reviewed alone, and a one-shot run starts no background run at the end of its turn (ADR-0067).
- Privacy: the window's requests, texts and tool calls go to the same endpoint and key that already receive the whole conversation; no new recipient. It spends the user's own credits, which is why it has the daily cap and why `hooks.llm.disabled` and `hooks.every.goal-review` 0 turn it off ([ADR-0050](0050-credits-usage-models-and-low-balance-notice.md)).
- The light model's rate limit is shared with the halt guard's judge: a limit hit by background reviews makes `HookLlm` return nothing, so the halt guard's judgement of that turn is silent. The doctor line's error counts and the hook log show it; no design change for now.
- Requests are quoted from the records, which were redacted; a request with a redacted secret no longer matches the conversation and is not quoted.

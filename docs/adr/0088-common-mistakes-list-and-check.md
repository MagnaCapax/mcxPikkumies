# ADR-0088: A background and end-of-turn check against the common-mistakes list

## Metadata
- Author: Aleksi Ursin / MCX (with Väinämöinen)
- Date: 2026-10-20
- Status: Accepted

## Context
[ADR-0063](0063-common-mistakes-list-changing-data-and-no-python-tools.md) added `doctrine/antipatterns.md`, a list of 53 common mistakes read on demand, and a one-line pointer to it in `doctrine.md`. A list the agent only reads when it thinks to is no check: nothing catches a mistake that slipped through anyway. The operator asked for a check that runs on its own, against the agent's own recent replies and commands, and adds the matching entry's fixed text to the next turn, without adding a second timer, spool or background worker beyond the one the sibling interval-unit ADR already built.

Facts read for this decision (build-time, not assumed):
- `lib/HookAsync.php` already supports `every` (its `passed()` and `path()` methods, both public, are the only pieces a synchronous caller needs to check "has this unit's interval passed" without going through the async wake-flag path; verified by reading `lib/HookAsync.php:82-91` before writing this check).
- `lib/HookRun.php`'s `beginRun()`/`endRun()`/`cursor()`/`state()` (all public, `lib/HookRun.php`) already do the claim-the-run-and-share-the-state work a synchronous caller needs; nothing was added to either file.
- `lib/HookLlm::chat(array $messages, $timeout = 6, $maxTokens = 60)` (`lib/HookLlm.php:14`) sets `temperature: 0` itself; a caller does not need to.
- `hooks/worker.php` already claims an interval unit's run (lock, stamp, cursor, state) before it ever runs the unit's script, and saves what the script answers (`lib/HookPending.php::store`). The background half of this check (`hooks/review/antipattern-check/antipattern-check.php`) therefore never calls `Antipatterns::forTurn()`/`beginRun()`/`endRun()` itself: calling `beginRun()` a second time, from a different file handle on the same already-locked `.lock` file, in the same process, fails to acquire the lock (`flock()`'s own documented behaviour for a second file descriptor on the same file) and would have silently turned the background half off.
- `lib/HaltJudge.php` (ADR-0047) is the one decision function for both end-of-turn callers (`lib/HaltRun.php`, `hooks/halt/halt-guard/halt-guard.php`) and is left untouched by this ADR: its verdict's `message` is either a built sentence (`continue`, `done-wrapup`) or `null` (`chat`, `waiting`, `allow`, `failopen`) -- a clean two-way split this check hangs its own behaviour on, needing no new verdict names.

## Options Considered
- **A second interval, spool or worker just for this check.** Rejected: ADR-0067 already built the one mechanism an interval unit needs; a second one duplicates it for no reason.
- **Let the model's own words reach the agent.** Rejected, for the same reason ADR-0047 never lets the halt judge's free text through: a transcript or tool output the model is shown can say "ignore previous instructions"; only fixed PHP text, never the model's reply, may reach the agent.
- **One shared check, two callers, one shared stamp/interval/shown-ids state (chosen).** The background unit (`hooks/review/antipattern-check/`) and the two end-of-turn callers read the session's own words (replies and tool calls, or the turn's final answer and commands) and ask the same one question of the same light model, but never inside the same interval twice, because both sides claim the same unit id's stamp (`lib/HookRun.php`, `lib/HookAsync.php`).

## Decision
- **`lib/Antipatterns.php`** (new): `entries()` parses `doctrine/antipatterns.md` into `[id => shape, cue, do]`; `rubric()` builds the model's input from `shape` and `cue` only, never `do`; `ask()` makes the one `HookLlm::chat` call (20 s, 80 tokens, or less when a caller's own budget is shorter) with a fixed instruction, the rubric, and the checked text, delimited and marked as data with `HaltJudge::DATA_NOTICE`; `commandText()` cuts each command line to 300 characters before it reaches either the prompt or the grounding check, so one long command cannot blow out the request (review finding M1); `parse()` keeps at most two `id | words` lines whose id is real, whose words (case/whitespace-folded, at least 12 characters) are found in the checked text itself, and whose id was not already shown this session -- everything else in the reply, including a line that is not that exact shape, is dropped and counted, never read as an instruction; `lines()`/`resumeMessage()` render only the file's own fixed sentences for the flagged ids, capped at 1100 characters (raised from an initial 500, which cut a majority of two-id messages and even one single entry mid-instruction -- review finding L6); `reserve()` spends one call of the shared daily ledger (`lib/HookLedger.php`, ADR-0071) before any model call, default 48/day, `hooks.dailyCalls.antipattern-check`; `log()` writes one line per run to `local/logs/antipatterns/YYYYMMDD.jsonl` (0700/0600), the same retention as the halt-guard log, holding only the outcome, the ids, the dropped count, the input size and the time -- never the text, the reply, or the commands.
- **`hooks/review/antipattern-check/`** (new unit, `event: transcript`, `every: 300`, `wake: reply, tool`, `timeout: 30`): the background half. Reads the session's reply texts and tool calls since its last run, skips a scheduled (`cron_`) session and a spent ledger before calling the model, calls `Antipatterns::ask()`/`parse()`/`lines()` directly (never `forTurn()`: `hooks/worker.php` already holds the run), and answers `{"context": lines, "state": {"shown": ids}}`. No reply in the window: `{"skip": true}` (the cursor stays put, so a tool-only window is seen again with the next reply instead of being lost -- review finding L8), logged `skipped:no-replies`.
- **`Antipatterns::forTurn()`/`apply()`**: the end-of-turn callers' entry point, called by `lib/HaltRun.php` and `hooks/halt/halt-guard/halt-guard.php` right after `HaltJudge::evaluate()`, never inside it. `forTurn()` checks `antipatterns.disabled`, skips a scheduled (`cron_`) session the same way `goal-review.php` does, looks up the shared unit through `HookInterval::on()`, checks the shared stamp's interval itself (not the wake-flag path, since this caller has no spool records of its own to wait for), claims the run, reserves the shared ledger, asks and parses, re-stamps "now" once more while still holding the lock (a competing worker's `again()` call takes no lock of its own and can otherwise shorten the just-claimed interval down to its own 30 s retry delay -- review finding L4), and returns the grounded ids. `apply()` turns a verdict plus those ids into either an appended message (verdict already has one: `continue`, `done-wrapup`) or a resume with `resumeMessage()` (verdict has none: `chat`, `waiting`, `allow`, `failopen`), unless `antipatterns.resume` is `false`. Both callers reuse their own existing one-shot-resume guard for that second case -- `$wrappedUp` in `lib/HaltRun.php`, `wrapup_sent` (via `HaltState::markWrapupSent()`) in `hooks/halt/halt-guard/halt-guard.php`, the same slot `done-wrapup` already uses -- so ADR-0047's bound of 3 continues plus one final resume is unchanged; `halt-guard.php`'s existing `attempt >= 3` refusal and its `wrapup_sent` early exit are untouched. `halt-guard.php` tracks its own start time and gives the check only what is left of its own 30 s unit timeout (capped at 27 s, skipped outright under 5 s left), since the judge call ahead of it can already use most of that budget and a killed check must never cost the judge's own `continue` (review finding H-2).
- **Settings** (`lib/Config.php`, `lib/ConfigureTiers.php`): `antipatterns.disabled` (`['bool','person','free']`, like `halt.disabled`: person to turn off, free to turn back on) turns off the background unit and both end-of-turn callers together, as a second, explicit switch alongside the `hooks.every.antipattern-check=0` off switch below -- kept rather than deleted, because the two read differently in `local/config.php` and a person editing the file by hand may reach for either name; `antipatterns.resume` (`['bool','free','person']`, the positive-sense direction, like `ssh.blockUnknown`: free to turn off, person to turn back on -- the review caught this copied backwards from `halt.disabled`'s negative sense, review finding M2) turns off only the end-of-turn one-shot resume; `hooks.every.antipattern-check` sets the shared interval (60 to 3600 s, ADR-0067) and, set to `0`, is a second, free-tier way to turn off all three callers (the same precedent as `goal-review`'s own interval, ADR-0071: "longer or off is free ... each run spends credits"); `hooks.dailyCalls.antipattern-check` sets the shared ledger's cap (default 48, `lib/HookLedger.php`); `hooks.async.disabled` and `hooks.llm.disabled` also apply, as they do to every interval unit and every hook model call.
- **Cost**: at most one light-model call per session per interval (default 300 s) across all three callers combined, reserved against a shared daily ledger before the call is made (default 48/day/account, a failed or timed-out call still spends its reservation), at most 80 output tokens, at most 1100 characters injected, each id shown once per session. The minimum request is the ~7.4 KB rubric (about 1.9k tokens) on every call; the worst case, at the defaults, is the full 8000-character final answer plus 40 commands of up to 300 characters each, on the order of 20 KB (review finding H4, measured before the M1 cut). A grounded id can turn a verdict that would otherwise end the turn silently into one extra **main-model** turn (the one-shot resume) -- a cost this line previously left out (review finding L1).

## Consequences
- The list from ADR-0063 now has a check behind it, without a second timer, spool or worker: the background unit and the two end-of-turn callers share the one the sibling ADR built.
- The model's own free text never reaches the agent, by construction: only a grounded id's fixed file text is ever shown, and grounding requires the quoted words to already be present in the checked text, not merely asserted by the model.
- The `HaltJudge::decide()` verdict table and its fixed sentences are unchanged; this ADR only reads and extends the verdict's `message` field after the fact, in the two callers, never inside `lib/HaltJudge.php`.
- **Trade-off:** the antipattern-triggered resume and a genuine `done-wrapup` share one wrap-up slot per run. If this check's resume fires first, a `done-wrapup` later in the same run (the lesson-save-and-idea closing turn) is suppressed for that run, not merely delayed -- accepted so ADR-0047's bound of 3 continues plus one final resume is never widened, rather than opened to two independent slots (review finding L7).
- `tests/AntipatternsTest.php` (T2/T3), `tests/HaltRunTest.php` (T4), `tests/HaltHookTest.php` (T5) and `tests/AntipatternCheckUnitTest.php` (T7) fail when grounding, the shared interval, the shared one-shot-resume slot, or the background unit's reply-or-nothing behaviour regresses; `tests/AntipatternsReviewFixTest.php` fails when the daily ledger, the halt-guard time budget, the command-line cut, the UTF-8-safe encode, the resume tier, the scheduled-session skip, the stamp re-check, the no-replies `{"skip":true}`, or the array-safe final answer regresses (independent review, 2026-10-20).

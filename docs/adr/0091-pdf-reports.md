# ADR-0091: PDF reports from a reviewed report JSON, printed by the server's Chromium

## Metadata
- Author: Aleksi Ursin / MCX (with Väinämöinen)
- Date: 2026-10-20
- Status: Accepted

## Context
The operator asked on 2026-10-20: "pikkumies needs super stylish, easy to read PDF report generation tooling as well, a bit like ours, but take the styling, user experience, data review etc. protocols further than ours". "Ours" is the report pipeline of the operator's own agent: two hand-filled HTML templates printed to PDF by a headless Chromium. Reading those templates and their pipeline showed what to keep and what to take further:
- kept: a light print theme with CSS tokens, serif headings, mono labels, tabular figures, a verdict box first, labelled severity chips;
- missing there: no charts in the PDF, no page numbers or running header, no contents page, sources checked only by a review after rendering and never shown in the PDF, and two copies of the stylesheet that drift apart.

Facts checked for this decision:
- Pikkumies has no PDF capability and no Composer dependencies; PHP 7.3 only; GD and Imagick are not on every host, so charts cannot be raster images made in PHP.
- The PMSS updater installs Debian's `chromium` package on Debian 12 and 13 hosts with room, for agents that run inside an account, and never the setuid sandbox helper; the browser is expected to run in a namespace made with `unshare --map-root-user` (PMSS ADR-0123, `scripts/lib/update/apps/chromium.php`).
- Chromium prints CSS page-margin boxes (`@page { @bottom-right { content: counter(page) " of " counter(pages) } }`) since version 131. Rendered on 2026-10-20 with the Chromium 145 headless shell (`--headless --no-pdf-header-footer --print-to-pdf`, inside `unshare --map-root-user --net`): three pages printed "Page 1 of 3" to "Page 3 of 3", and `@page :first` removed the header from the first page. A `position: fixed` footer repeats on every page but cannot count pages, so margin boxes are the only page-number method that works with the CLI print (it has no header/footer template flag).
- On the development host the full Chrome-for-Testing 145 build with `--headless --print-to-pdf` loaded the page and then never wrote the PDF (killed after 90 s, also without the namespace); the headless-shell build of the same version printed in under a second. Debian's `chromium` has not been run here. Hence the hard timeout with a process-group kill, and the headless shell first when installed.

## Options Considered
- **A PHP PDF library (TCPDF, mPDF, Dompdf).** A large vendored dependency, a PHP 7.3 compatibility pass, and weaker CSS than a browser; rejected.
- **Hand-filled HTML templates per report, as ours are.** Duplicated styling and no machine check of the numbers; rejected.
- **A report JSON, a deterministic data review, one stylesheet, inline SVG charts written in PHP, printed by the server's Chromium.** Chosen.

## Decision
- **The kit** is `pikkumies/lib/report/`: plain PHP 7.3 with no Pikkumies dependency (so another project can copy the directory as it is): `ReportKit::decode()` (document model), `ReportKit::lint()` (data review), `ReportKit::html()` (one self-contained page), `ReportKit::example()` (the reference document).
- **Every number is a figure** `{value, unit, source, as_of}`. Numbers inside text are `{fig:<id>}` references to declared figures. A table or chart may give the source and date for all its numbers. Each figure prints with the number of its source; the appendix "Where each number comes from" lists every source and every figure with value, source, date and age. A figure without a source prints with a red dagger.
- **The data review** runs before every render, by fixed rules (the same input always gives the same findings). Errors: a number without a source, a reference to an undeclared figure, a value that is not a number, a declared total (table total row, donut total, `sum_of`) that differs from its parts by more than their rounding plus 0.1%, a share outside 0-100% (unless marked as a change), a figure dated after the report, one label with two values at the same time, an empty section. Warnings: a figure older than `stale_days` (default 7) before the report date, a sourced number without a date, a number typed into the text instead of referenced, a sentence over 25 words, one label with two values at different times, and a bar, column or line chart whose values differ by less than 3% of its axis span (it cannot show the difference it exists for; bar axes stay at zero, because a cut bar axis misleads, so the fix is a table, a bullet chart or the gap in words). The result is the Review page (every check, also the passed ones, and every finding) and the status line; `render --strict` refuses to render with any error.
- **The page**: cover (verdict with a labelled state, three to six KPI cards with limit meter and sparkline, the report's facts and review result, how to read it); contents when there are more than three sections; numbered sections with a one-sentence takeaway; Review; appendix. A4, running header (title, data date) and footer ("Page X of Y") in page-margin boxes, none on the cover. A state is always an icon of its own shape plus a word, never colour alone. Breaks: a heading never ends a page; cards, figures, callouts and table rows are not split; table headers repeat.
- **Charts** are inline SVG written in PHP: line, area (with an optional low-high band), column, bar, stacked bar, donut, sparkline, bullet. Each has `<title>` and a `<desc>` that states the range, last value and extremes in words. Lines also differ by dash and carry a direct end label; fills after the first carry a texture; every series is in a legend or a label; the categorical colours are a validated order. Many columns get labels on the highest, lowest and last only.
- **What the review does not cover**: it reads figures and text fields; chart titles and KPI labels are names and are not scanned for typed numbers, and `--strict` refuses errors only (warnings render and are listed). A text field is checked for typed numbers, not proved: a number spelled out in words passes.
- **Limits**: at most 2000 rows per table, 2000 points per series, 12 series and 500 categories per chart, 64 KiB per text field and 8 MiB of JSON; at most 100 findings per check are listed (all are counted); HTML over 20 MiB is not printed. Each refusal says "summarise first".
- **Safety of the page**: every value is HTML-escaped (CSS strings through CSS escapes); a `Content-Security-Policy` meta of `default-src 'none'; img-src data:; style-src 'unsafe-inline'; font-src data:`; no script; system font stacks only, nothing is downloaded.
- **The unit** `tools/documentation/report` (verbs `render`, `lint`, `templates`, `example`) writes only to `local/reports/` (0700, files 0600, temp file and rename; `--out` is a file name, never a path). `render` prints with `setsid unshare --map-root-user --net <chromium> --headless --no-sandbox --disable-gpu --user-data-dir=local/state/tmp/report-XXXX --no-pdf-header-footer --print-to-pdf=<out> file://<html>` plus network-off flags (no background networking, a host resolver that finds nothing, a dead proxy with no loopback bypass). Without `unshare`, or where an unprivileged namespace cannot be made, it runs with the flags only and says so in `isolation`. The browser is `chromium-headless-shell`, `chromium` or `chromium-browser` from PATH, or `--browser <absolute path>`. A timeout (default 90 s) kills the whole process group, which is also killed after a normal exit; the profile directory is removed. Without a browser the HTML is written and the status says how to print it. `--no-sandbox` is required, not chosen: PMSS installs no setuid sandbox helper, and under `--map-root-user` Chromium runs as uid 0 in the namespace, where it refuses to start without the flag. The page has no script (CSP), no network and runs as the account's own user, so what the sandbox guards against (a hostile page exploiting the renderer) is narrowed to an escaped, script-free page made from the account's own data; a renderer bug is still not ruled out, and the account's own permissions are the remaining boundary. The `--version` probe has its own 10 s limit and a browser that fails it is not started again. A Chromium older than 131 still prints, with a hint that page numbers are missing.
- **Templates** build report JSON from the account's own data and never type a number: `account-health` (`system-status account` and the telemetry history in `local/state/telemetry/<source>/YYYYMMDD.jsonl`), `services-overview` (`local/state/services.jsonl`), `move-report` (`local/state/moves/<id>.jsonl`, only the step, torrent id, result and message fields).
- The unit lives in the documentation category but is not a documentation source, so it is exempt from that category's shared `search` and `list` verbs (named in the category README and the contract test).

## Consequences
- A report is checkable before anyone reads it, and the PDF shows its own provenance and review.
- Rendering depends on a Chromium on the server; hosts without one get the HTML, which prints from any browser.
- The CLI print of Debian's full `chromium` build is not verified on the development host (see Context); the timeout bounds the failure, and the first real host run should confirm it.
- The review checks consistency, not truth: a wrong number with a source and a date passes. The source numbers make it quick to check by hand.
- Follow-up outside this repository: the operator's own agent can copy `lib/report/` and move its two templates onto it.

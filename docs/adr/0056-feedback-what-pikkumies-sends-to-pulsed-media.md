# ADR-0056: /feedback, the one thing Pikkumies sends to Pulsed Media

## Metadata
- Author: Aleksi Ursin / MCX (with Väinämöinen)
- Date: 2026-10-18
- Status: Accepted; amended 2026-10-19 twice (the occasional question; approvals off) and 2026-10-20 twice (no longer the one thing; a rating-only send at exit), see the amendments at the end

## Context
The operator's request of 2026-10-18: "We should probably have feedback API option ... Basicly integrated with pikkumies, so people can /feedback and that sends us crucial information + transcript and we store it for later analysis ... private secure storage, only for us", and on the place: "should we do it separately a pikkumies.mcx.fi domain for functions like this? I think we will regardless need to create one so we can upsell power functionality".

AGENTS.md says Pikkumies "never sends anything off the machine that the user did not ask it to". [ADR-0032](0032-settings-configure-skill-first-run-and-install-flags.md) keeps `privacy.telemetry` a setting with no sender and says a sender needs its own ADR. This is that ADR, for feedback only.

Facts this rests on, checked 2026-10-18 in Hermes v2026.9.24:
- Hermes' built-in `/debug` uploads system information and log tails to a public paste service. Typed in the terminal it passes `yes=True` and asks nothing (`hermes_cli/cli_commands_mixin.py`, `_handle_debug_command`); from a chat platform it uploads first and shows the privacy notice with the links (`gateway/slash_commands.py`, `_handle_debug_command`). Only `hermes debug share` on a terminal asks y/N (`hermes_cli/debug.py`, `_confirm_upload`). `/debug local` uploads nothing.
- A tool unit is a skill the model runs ([ADR-0015](0015-tool-units-one-skill-per-tool.md)), so a y/N inside the tool, or a `--yes`, is answered by the model. Hermes' human-approval gate is not ([ADR-0020](0020-deletes-need-the-users-approval.md)): a `pre_tool_call` hook answering `approve` makes Hermes ask the user, the model cannot answer, and unattended runs are refused unless approvals are turned off (ADR-0020).
- `hermes sessions export <dir> --format md --session-id <id> --redact --lineage logical` writes one session, compacted turns included, with secrets removed from the messages (`hermes_cli/sessions_cmd.py`, `redact_session_data`). Its redaction leaves a bare `vsk-` key in prose untouched.
- Hermes sets `HERMES_SESSION_ID` in the environment of every command it runs (`gateway/session_context.py`).

## Options Considered
- **Point users at Hermes `/debug`.** Public, and a typed `/debug` asks nothing. Rejected for anything private.
- **Disable or wrap Hermes `/debug`.** Hermes stays vanilla ([ADR-0033](0033-vanilla-hermes-git-checkout-updated-separately.md)) and has no setting that removes a built-in command. Rejected; the feedback skill and README say `/debug` is public and point to `/feedback` or `/debug local`.
- **A y/N in the tool before sending.** The model can answer it, and text the agent reads (a torrent name, a file) can steer it. Rejected.
- **Open a support ticket with the transcript.** Puts the transcript in the general ticket queue and needs billing credentials where the feedback arrives. Rejected.
- **Send in the clear over HTTPS and encrypt on the server.** The plaintext would pass through the receiving server's memory. Rejected: the client seals it.
- **Retry automatically when sending fails.** A send at a time the user did not choose, outside the approval gate. Rejected.
- **Read the key the way the agent does (`Provider::resolve`).** It prefers `~/.pikkumiesKey`, the user's own provider: feedback would carry that provider's key to Pulsed Media. Rejected: only `~/.virsilipasKey`, and only a `vsk-` key.

## Decision
- **`tools/system/feedback/`** (a tool unit, ADR-0015) with `draft`, `send <id>` and `list`.
  - `draft --text T | --text-file F [--no-conversation]` builds the payload and saves it once under `local/state/feedback/<id>.json`, mode 0400, where `<id>` is the first 32 hex digits of the file's sha256: the text (at most 20,000 bytes), the current conversation (exported as above into a fresh 0700 directory under `local/state/feedback/`, never a shared `/tmp`, read once and deleted; export directories older than 10 minutes, left by a killed draft, are removed on the next draft), its session id and title, and the Pikkumies commit, Hermes version and PMSS version. The export's header also carries the session's model, provider and working directory. Both texts go through `lib/Redact.php`, line by line: `Cli::cleanString`, the shell forms the command log already removed, and the common password and key forms of config files, headers, PEM blocks and token prefixes (`vsk-`, `sk-`, `AKIA`, `ghp_`, `xoxb-`, JWT); the command log uses the same class. These are common forms, not every secret, so the user reads the draft before sending. A regex engine error stops the draft with an error, never an emptied text. The conversation is cut to its newest 1.5 MB before redaction and the whole payload stays under 1.5 MB encoded; a cut conversation says so. It prints the size, the session, whether the conversation is in and how the text starts. Nothing leaves the machine.
  - `send <id>` refuses a draft whose sha256 no longer starts with its id, seals it to Pulsed Media's public key (`config/feedback-public-key.txt`, a libsodium sealed box) and posts it to `https://pikkumies.mcx.fi/v1/feedback` with the `vsk-` key as the Bearer token, through `lib/Http.php`. When it fails, the draft stays and the error says so, and says that trying again will not help after a 4xx other than 429; nothing retries by itself. After the server takes it (201) the draft becomes `<id>.sent.json`, which is never sent again, so a remembered approval cannot send a duplicate. `load()` accepts only the known fields with their types. Without sodium it says what is missing and keeps the draft.
- **`hooks/guard/feedback-send/`** (pre_tool_call, `failClosed: true`): the terminal command exactly `php <this Pikkumies' feedback.php> send <id>`, alone, with an absolute (or `~/`, expanded with HOME) canonical path, gets `approve` with `rule_key` `pikkumies-send:<id>`. The message is built from the draft file itself: where it goes, that it is linked to the account through the key, its size, the session id and title, that it carries version numbers and the session's model, provider and working directory, the path of the whole file, and last, on one line with quotes escaped, the first 400 bytes of the text. The forms of a feedback send it can see are blocked: a feedback path followed by the verb `send` (only the word right after the path counts, so a draft about a send button runs), `FeedbackSend` or `FeedbackDraft` with the word send, and a feedback path with shell expansion (`$ * ? [` or a backtick) and the word send, in a terminal command, code, a background process's input, `write_file` or `patch` content and a scheduled job; and a missing, changed or already sent draft. It sorts before `guard-destructive`, and a block wins over any approve.
- **The prompt is a safety prompt, not a security boundary.** It catches the agent's own and casual sends. An agent steered by text it reads runs as the same user and can still run the sender some other way (a relative path from the tool's directory with a glob, code that rebuilds the sender), as it could run curl to send anything anywhere; AGENTS.md says hooks are safety prompts. What the sender sends is sealed to Pulsed Media either way.
- **USAGE `changes`: `sends`** marks a verb whose data leaves the machine. The guard contract test checks that no `sends` example is let through unasked.
- **Feedback is not telemetry.** It is sent only when the user approves one specific payload, so `privacy.telemetry` does not gate it, and it never sends anything on its own. AGENTS.md's privacy rule says so.
- **What the server keeps:** the sealed blob, the sha256 of the key, the size and the time. Only Pulsed Media's private key, kept off that server, opens it. The Pulsed Media privacy policy says what is kept, for how long and how to have it deleted; the server takes nothing before that text is published.

## Consequences
- The user is asked before every send the agent makes in the plain form, and sees what goes out. An agent steered into rebuilding the sender can still send without the prompt, sealed to Pulsed Media, as it could already send data anywhere with curl.
- Pulsed Media gets the conversation that explains a problem, sealed end to end.
- `/debug` stays as Hermes ships it; the docs say it is public.
- The server cannot check what a sealed payload contains: a client could send junk up to the size limit. The server's per-key daily limit and storage cap bound it.
- Feedback needs a Pulsed Media AI key and PHP with sodium; without either, the draft is kept and the tool says why.

## Amendment 2026-10-19: the occasional question, opt-in, and a prompt that says what goes
**Context.** The operator's request of 2026-10-19: "virsilipas now has feedback option ... a feedback skill to be used, [like a coding agent named in the request,] randomly asking if you'd like to give feedback etc. and then confirms if you truly want to send that feedback saying that transcript will be sent to virsilipas, full transcript and system information ... honor our privacy policy and privacy first, fully opt in only". The feedback option is the intake at pikkumies.mcx.fi above; the account link is the AI credits (Virsilipas) key. Two facts shaped this: Hermes shows only about `HookUnits::APPROVE_SHOWN` (350) characters of an approve message for sure on a 24x80 terminal, and this guard's message used to spend them on the draft id and the account link before saying what the conversation part was; and with approvals off (`--yolo`, `HERMES_YOLO_MODE`) Hermes lets an approve through with nobody asked (ADR-0020).

**Options considered.**
- Gate the question on `privacy.telemetry`: it defaults on (ADR-0032), so the question would be opt-out. Rejected.
- Ask in a `pre_verify` nudge: it forces an extra model turn, on the user's credits. Rejected.
- Ask on the terminal after Hermes exits: a second send path outside this guard. Rejected.
- Name the destination "Virsilipas" in the prompt: the privacy policy says the credit service never stores prompt text; the feedback goes to Pulsed Media's feedback service at pikkumies.mcx.fi, linked through the AI credits key. Rejected for the prompt.
- Leave sends under `--yolo` as they were: the operator asked for a confirmation before anything leaves. Rejected.
- The coding agent the operator pointed to asks for session feedback by default and lets users turn it off; this one is off until the person turns it on.

**Decision.**
- A setting `feedback.ask`, default off (`lib/Config.php`). Turning it on is asked ([ADR-0059](0059-settings-tiers-free-asked-and-the-persons-own.md) tier `approve`: Hermes asks the person when the agent changes it); turning it off is free.
- At the first interactive start on a terminal, one question offers to turn it on (`FeedbackAsk::offerOnce`, called from `bin/pikkumies` after the terms). Enter, any other answer or end of input is no; a marker under `local/state/feedback-ask/` is claimed before asking, so it is asked once ever.
- Hook unit `hooks/system/feedback-ask` (`pre_llm_call`, fails open, 2 s): when the setting is on, in a session on Hermes platform `cli` or `tui`, at `PIKKUMIES_DEPTH` 1 or less, without `HERMES_YOLO_MODE`, with at least 4 user messages, for about 1 session in 5 (the first 16 bits of the session id's sha256, mod 100, under 20) and at most once in 7 days, it writes the marker `local/state/feedback-ask/asked` and then gives the turn one sentence: ask once, in one line, at the end of the answer. No marker written, no sentence. The rate, the 7 days and the 4 messages are starting values, not measurements.
- The send prompt (`tools/system/feedback/FeedbackPrompt.php`) opens with where it goes and what goes: the user's text, the conversation transcript (whole, its newest 1.5 MB, or none) and system information (model, provider, folder, versions), to Pulsed Media at pikkumies.mcx.fi, locked, linked to the account; then the size, the file holding all of it and the start of the text, cut to fit. The whole message passes `HookUnits::approveShown()` (at most `APPROVE_SHOWN` characters, the check every unit uses since ADR-0020's amendment of the same day); one that cannot fit is a block. The draft id is in the file path; the session id and title, and the command, moved out of the prompt (the draft record and the file still show the session). What the draft holds is unchanged (`FeedbackDraft::FIELDS`).
- The plain send is blocked, not asked, when `HERMES_YOLO_MODE` is set (`NestedAgent::approvalsOff`, Hermes' truthy set) or at `PIKKUMIES_DEPTH` 2 or more; the message gives the command for the person to run in their own terminal. This is an exception to ADR-0020's "in that session (depth 1) yolo still lets the guard's questions through", for this guard only.
- The feedback skill: act on the question only after the user's yes; ask once; a no ends it; "never ask again" turns the setting off; never offer to turn it on unasked; when showing a draft, say what sending gives Pulsed Media and where.

**Consequences.**
- Nothing is asked unless the person turned it on, and the question sends nothing; every send still goes through this guard.
- A `/yolo` typed inside a session is in-process state no hook can see: there the question can be asked and the send goes through unasked, as Hermes skips every question; the skill's disclosure is the only notice. A one-shot run resumed from a long session can carry the question at the end of its answer.
- Users who run `--yolo` and use `/feedback` now run the send command themselves.
- About 70 tokens in each turn that asks, on the user's credits.
- Code: `pikkumies/hooks/system/feedback-ask/`, `pikkumies/tools/system/feedback/FeedbackAsk.php`, `pikkumies/tools/system/feedback/FeedbackPrompt.php`, `pikkumies/lib/NestedAgent.php`; tests `tests/FeedbackAskTest.php`, `tests/FeedbackPromptTest.php`.

## Amendment 2026-10-19: approvals off, the send confirmed in the chat
**Context.** [ADR-0073](0073-no-questions-no-deferrals-one-reviewed-exception.md)'s amendment of the same day pins `approvals.mode: "off"`, under which Hermes approves this guard's `approve` with nobody asked, as it does under `--yolo` (`tools/approval.py` `_run_approval_gate`). Left as it was, a feedback send would leave the machine without the person's yes.

**Decision.** The send no longer depends on Hermes' prompt. The orchestrator's ask policy never passes the `approve` on: it reviews the call against the user's own recent messages with R2 forced to yes, so only the user's explicit yes to this send (R1 "yes", R3 "no") lets a re-run through; until then the call is blocked with a fixed message telling the agent to say in one line what would be sent and to run the command again after the user says yes. Where no yes can be checked (a messaging gateway, a scheduled run, an agent started by an agent, `halt.disabled`, or no review answer) the send stays blocked and the agent gives the command for the person to run. `NestedAgent::approvalsOff()` still reads only `HERMES_YOLO_MODE`, so under `--yolo` the guard keeps refusing the send outright; reading the pinned mode there too would refuse every send in every session.

**Consequences.** A `/yolo` typed in a session no longer lets the send through unasked. The question `feedback.ask` adds is unchanged. Not verified live: how a real light model judges a plain "yes" after the agent's one-line description of the send. Test: `tests/ApprovalsOffTest.php`, `tests/HookMergeTest.php` (the shipped send through every shipped unit, with no session, is a block).

## Amendment 2026-10-20: no longer the one thing
**Context.** [ADR-0089](0089-support-tickets-with-the-ai-key.md) adds `/ticket`, a support ticket opened with the AI key, as a second thing Pikkumies sends to Pulsed Media.

**Decision.** AGENTS.md's privacy rule names both. The draft store and the send check this ADR decided moved, unchanged in behaviour, into `lib/DraftStore.php` and `lib/SendGuard.php`, which `guard/ticket-send` shares; `FeedbackSend::pmKey` reads the key through `Provider::pulsedMediaKey`. Everything else here stands.

**Consequences.** One check for both senders, so a fix to it reaches both. Tests: `tests/FeedbackTest.php` unchanged, `tests/TicketTest.php`.

## Amendment 2026-10-20: a rating-only send at exit, and one ask budget
**Context.** The operator's request of 2026-10-20: "We should sometimes show the user request to submit feedback to us so we can better learn, imitate the feedback how well it is doing thing from claude code, not very frequently and mionimum session duration ahs to be i think 45mins and 500k tokens (total cross compacts etc.) perhaps?". The first amendment above rejected "ask on the terminal after Hermes exits" as a second send path outside this guard. That rejection was about the transcript. A rating asked mid-session would have to go through the model: the person's "3" becomes a full-context model request on their credits, and the model could answer it itself. [ADR-0097](0097-session-rating-at-exit.md) decides the rating; this amendment records what it changes here.

**Decision.**
- A rating-only send path exists, separate from `/feedback` and `/ticket`: `FeedbackSurvey`, called by `bin/pikkumies` after Hermes exits and nowhere else. It sends `{v, kind: "rating", rating 1-3, minutes (rounded to 5), tokens_k (rounded to 100k), model (a name; a path is sent as "other"), versions (each at most 64 printable characters)}` through `FeedbackSend::send` (the same sealed box, key file, endpoint and `vsk-` Bearer key), with a 5-second timeout (`send` takes an optional timeout, default 60 as before). No session id, conversation, path or usage count. It is sent only when the person presses 1, 2 or 3 on a line that says what goes and that it is linked to their account; what was typed before the line appeared is thrown away; the person's own keypress on the terminal, outside the model, is a stronger yes than the chat review this guard relies on. It is never retried.
- This guard also blocks the agent naming `FeedbackSurvey::` (or the class as a quoted callable) in a command, code, process input, a file or a scheduled job. Reading the file stays allowed. It is a safety prompt, as above.
- One ask budget for both askers: `local/state/feedback-ask/next`, whose mtime is the earliest next ask, claimed under a lock before anything is shown; and never twice in one run (`asked` in the run's counter file). Eligibility for both: 45 minutes since the interactive start AND 500,000 tokens across the run, depth 1 or less; `HERMES_YOLO_MODE` makes no difference (`--yolo` is the default run mode, ADR-0073 amendment 2026-10-20). The 4-user-message gate is dropped (compaction shrinks the history it counted); the mid-session line keeps its 1-in-5 draw, now keyed by the run id, so most eligible runs get the rating instead. After an ask: 14 days (the mid-session line, or a rating given), 30 days after a dismissed rating (0, Enter or 20 seconds of silence), and `n` turns `feedback.ask` off. These replace the 7 days. The old `asked` marker still holds, with 14 days, for one release.
- `feedback.ask`'s description now says a rating is sent only when the person presses its number; the first start's offer says the same.

**Consequences.** The rating costs no tokens and no model can answer it. Exit can wait up to 20 seconds plus a 5-second send, only for an eligible run. People who turned `feedback.ask` on under the old text ("the question itself sends nothing") see the exact payload on every rating line before anything goes; whether to show them the first-start offer again is left open for the operator. Code: `pikkumies/tools/system/feedback/FeedbackSurvey.php`, `FeedbackAsk.php`, `FeedbackSend.php`, `pikkumies/hooks/guard/feedback-send/`; tests `tests/FeedbackSurveyTest.php`, `tests/FeedbackAskTest.php`.

# goal-review

The goal review: a background look, at most every 10 minutes, at what the user asked for in the session's last stretch and what the agent did about it ([ADR-0071](../../../../docs/adr/0071-goal-review.md)). It is an interval unit ([ADR-0067](../../../../docs/adr/0067-interval-hook-units.md)): it never runs inside a turn's wait, and its note reaches the agent at the start of the user's next turn.

- **When it runs:** after a finished answer (`wake: reply`), at most once per interval per session (`hooks.every.goal-review`, default 600 seconds; longer or 0, which turns it off, is free; shorter goes through the safety check, since each run calls the model on the user's credits).
- **When it skips** (logged): the window has no request (only follow-ups such as "ok thanks", slash commands, or Pikkumies' own continue and wrap-up texts, `lib/UserTurn.php`); its only request is the first turn's (that request then comes again with the next ones, so the first real review sees it); a scheduled session (a Hermes cron run, id `cron_...`); `hooks.llm.disabled`; the daily cap.
- **What it sends:** one request to the agent's own endpoint and key, with the light model (`lib/HookLlm.php`): the window's requests (8 at most, 1000 characters each), the agent's latest texts, its tool calls one line each, and up to 8 pages from the memory and documentation search and 8 tool units whose description shares words with the requests, at most about 16000 characters in and 300 tokens out. The same endpoint already receives the whole conversation; nothing goes anywhere else.
- **What the model does:** answers ten fixed questions with fixed tokens, one line each ("Q1: yes R2", "Q4: T1,T3", "Q7: diagnostics", ...). A reply with any other line, an unknown token or an id that was not offered is discarded whole.
- **What the agent gets** (at most 4000 characters, plus up to 8 quoted requests of 200 characters each, about 1.6k tokens at most): fixed sentences for the questions answered yes (a request still open, drift from the request, the user waiting, search memory again, a guess a command could check, the latest request changes data), the chosen tools as `php <path> --help`, the chosen pages by title and path, the checklist rows for the chosen kind of request, and the whole five-point checklist on the session's first review only. The user's requests are quoted by the orchestrator only when they occur word for word in the conversation Hermes passes it. Only chat (Q10 yes) or nothing to say: no note.
- **Cost:** one light-model call per run, at most one run per 10 minutes per session, at most `hooks.dailyCalls.goal-review` (default 24) calls a day per account, counted in `local/state/async/ledger.json` before each review. `hooks.goalReview.rounds` 10 makes each review ten calls, each seeing the last round's answers and free to change them, and only the last round counts; a review starts only when all ten calls fit in the day's cap, so the default cap then allows two reviews a day. Both are set by hand in `local/config.php`.
- **Log:** one line per run in `local/logs/goal-review/YYYYMMDD.jsonl` (directory 0700, file 0600, 7 files kept): the outcome (ran, skipped and why, discarded), the ten answers, the ids shown, the characters, and whether a tool or page shown last time was then used. Never a request, a reply or a call.

Advisory only: it adds a note, it never holds or changes a call. The agent's own account can edit the ledger and the state files, so the cap bounds a bug or a loop, not the agent (AGENTS.md: hooks are safety prompts, not security).

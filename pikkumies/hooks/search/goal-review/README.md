# goal-review

The goal review: a background check that the agent is still working on what the user asked for ([ADR-0096](../../../../docs/adr/0096-goal-review-v2-drift-check-by-time-and-tokens.md), which replaces the cadence and questions of [ADR-0071](../../../../docs/adr/0071-goal-review.md)). It is an interval unit ([ADR-0067](../../../../docs/adr/0067-interval-hook-units.md)): it never runs inside a turn's wait, and its note reaches the agent at the start of the user's next turn.

- **When it runs:** polled after a finished answer: while a review is not due it answers skip, so the next answer looks again (a short run, no model call); after a review or any other outcome the next look waits `hooks.every.goal-review` seconds (120; 0 turns it off). It reviews only when the run is due: the first time after 5 minutes and 75 000 tokens, then at most every 30 minutes and only after 600 000 more tokens (`hooks.goalReview.firstAfter`, `firstTokens`, `thenEvery`, `thenTokens`, set by hand in `local/config.php`). A call that gave no usable answer is tried again after 10, then 20, then 30 minutes; after three in a row it waits for the next regular review. Across all sessions of the account, two goal-review calls are at least 10 minutes apart (the ledger).
- **What it counts by:** the run file `local/state/session-counters/run-<key>.json` ([lib/SessionCounters.php](../../../lib/SessionCounters.php)). An interactive `pikkumies` start makes the key and exports it as `PIKKUMIES_RUN`; every model request of that start, delegated agents' included, adds its tokens, so a compression does not restart the count, and the spool of what the session did is kept across it too. A `hermes` the agent starts from its terminal is another process and keeps its own spool, so its prompts never count as the user's. Without the launcher (the desktop app, a gateway) the count and the spool are per Hermes session and start again at a compression. Memory and outside lookups are counted as they happen: a memory, knowledge-base or wiki search, a read under `memory/` or `session_search`; a web search or extract, a browser, the browse tool, a delegated agent, `curl`/`wget` of a web address, or the deep-research skill.
- **When it skips** (logged): not due yet (answers skip, so the next answer looks again); a scheduled session (a Hermes cron run, id `cron_...`); `hooks.llm.disabled`; no run counter; no request; the daily cap.
- **What it sends:** one request to the agent's own endpoint and key, with the cheapest light model of the main model's own family (`<main>-...`, or the light model chosen at start) by the rates the credits line already cached, never an embedding, speech, search, image or audio model (`hooks.goalReview.model`, then `hooks.model`, override it): every request of the session whole (a skill invocation as its name and the user's own instruction), the skills invoked, the offered tools and pages, and from the newest back the tool calls one line each and the start of the agent's texts, at most 30 000 estimated tokens (bytes / 3) in and 500 out. When the requests alone do not fit, whole requests are left out, never the first or the newest three, and the prompt says so; at most 999 are shown, numbered from R1. A request is stored up to 12 000 bytes; if the kept ones still do not fit, the longest is cut and marked, and the oldest activity goes, so the prompt never passes 30 000. The same endpoint already receives the whole conversation; nothing goes anywhere else.
- **What the model does:** answers 13 named lines: GOAL (a scaffold, thrown away), CURRENT (the request that sets the goal), four scores from 0 to 1000 or x (request clear, on task, needs memory, needs outside sources: the need only, the lookups are counted here), and the open requests, waiting, tools, pages, checklist kind, guessed and chat. Any other line, value or id discards the reply whole.
- **What the agent gets** (at most 4000 characters, plus up to 8 quoted requests of 200 characters each): a fixed header with the four numbers and the two lookup counts, then fixed sentences: drifting (strong only after 10 tool calls since the current request), a request that may be unclear (re-read it adversarially, name the reading, say what only the user can settle), memory or outside sources not checked when likely needed, a request still open, the user waiting, a guess a command could check, the chosen tools and pages, the checklist rows, and the five-point checklist on the first review. Nothing fired: "On track by this check". Only chat: no note. The user's requests are quoted by the orchestrator only when they occur word for word in the conversation Hermes passes it.
- **Cost:** one call per review, at most `hooks.dailyCalls.goal-review` (default 24) a day per account, each at most about 30k tokens in: about 732k input tokens a day at most.
- **Log:** one line per run in `local/logs/goal-review/YYYYMMDD.jsonl` (directory 0700, file 0600, 7 files kept): the outcome, the scores, the current request's number, the sentences that fired, the estimated input, how many requests were shown and left out, the gates, the model, and after a note whether lookups followed and the next on-task score. Never a request, a reply or a call.

Advisory only: it adds a note, it never holds or changes a call. The agent's own account can edit the counters, the ledger and the state files, so the cap bounds a bug or a loop, not the agent (AGENTS.md: hooks are safety prompts, not security).

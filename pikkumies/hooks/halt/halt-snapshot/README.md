# halt-snapshot

Runs on `pre_llm_call`, once per turn, before `halt-guard` (`pre_verify`) can run at the end of it ([ADR-0047](../../../../docs/adr/0047-halt-guard.md)): captures what the turn started with, so the guard has something to judge against once the turn is over.

- **Where:** `local/state/halt/<sha1 of session_id>.json`, one file per session, directory `0700`, file `0600`, written through a temporary name and a rename.
- **What it holds:** `user_message` (the latest user text), `tail` (the conversation so far, cut to the last 25% by characters — at least 12 000 when that much exists, at most 40 000, never splitting a message in the middle), `asked` (what the user wrote or saw, the ask review's only evidence, below), `turn_started` (when this turn began) and reset counters for the new turn (`continues`, `wrapup_sent`, `last_judged_turn`).
- **`asked`, the ask review's evidence** ([ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md), [ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md)): in a person's own session (`platform` `cli`, `tui`, `desktop`) the user's last three messages and the agent reply they answered, never tool output or the halt guard's own text. A messaging-gateway turn counts only when the gateway lets nobody but named senders in (`lib/GatewayAccess.php`: an explicit `<PLATFORM>_ALLOWED_USERS` or `GATEWAY_ALLOWED_USERS` list with no `*`, the turn's `sender_id` on it exactly, no allow-all or allow-bots variable set, no `dm_policy`/`group_policy` `open` in the environment or either `config.yaml`; anything unknown or unreadable counts as open), and then only the current message and the reply it answers, because a shared thread's earlier messages may be other people's. In a scheduled run (`platform` `cron`) it is the words recorded when the job was made (`lib/CronAuth.php`, `local/state/ask/jobs.json`, written by guard-destructive): the job's prompt is found where Hermes places it in the run's message, and the newest matching record gives its entries. Anything else (a delegated subagent, an unrecorded job, an unknown platform) gives none, and the irreversible kinds are refused there. A cron lookup writes `cron-auth` `hit` or `miss` to the hook log, never the words.
- **Who reads it:** `hooks/halt/halt-guard/` (`pre_verify`, inside the same Hermes process when the turn edited a file) and `lib/HaltRun.php` (the one-shot wrapper, after Hermes has exited, for a turn that never edited a file and so never triggered `pre_verify` at all).
- **Multimodal messages:** a message that is a list of content parts has its text parts joined; anything else is skipped.

Off with `halt.disabled` in `local/config.php`. Fails open: a write it cannot make simply means the guard has nothing to judge, so the turn ends normally (ADR-0047 is defense-in-depth, never a gate that can wedge a session).

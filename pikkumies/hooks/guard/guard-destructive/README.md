# guard-destructive

The delete guard ([ADR-0020](../../../../docs/adr/0020-deletes-need-the-users-approval.md)). Before each `terminal` or `execute_code` call, and each `process_manage` write or submit (text typed into a background shell), it checks the command:

- **Blocked** outright, with a message telling the agent not to reach the same effect another way, to finish the rest of the task and to say in one line what was refused: a recursive delete of a whole home folder written as `/home/<name>` (Hermes refuses the `~` and `$HOME` forms itself), filesystem formats, raw device writes, partition changes, raw drive writes (`badblocks` with `-w`, `hdparm` writes, erases and trims, `blkdiscard`, `nvme format|sanitize|write-zeroes`, `sg_format`, `sg_sanitize`, `mkswap` on a device, output redirected, copied or tee'd onto a disk, md `repair` into `sync_action` or through `mdadm --action=repair`; `GuardDrives.php`, [ADR-0094](../../../../docs/adr/0094-drive-health-screen-verdict-and-grade-on-one-server.md)), world-writable permissions, fork bombs, force pushes, a delete verb renamed through an alias or a variable, base64-decoded text run by a shell, reading stored passwords (`local/secrets/`, `rclone config show|dump`), and any call that names the halt guard's state (`local/state/halt/`) or the scheduled-job record (`local/state/ask/`), file tools included: they hold the evidence the ask review trusts ([ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md), [ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md)). Quotes and backslashes inside a word do not hide a verb (`r"m"` is `rm`).
- **A question for the ask policy** (`approve`, with the whole command in the message and a `rule_key` of that exact command; the safety check runs it or refuses it, and a refusal is reported, never asked, [ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md)): deletes the user may want, such as backup prunes, `rclone sync|move|purge`, torrent removes with data, `*arr` and media server deletes, plain `rm` and `rm -rf` (Hermes itself still refuses a recursive delete of `/`, the home or system folders), emptying a file (`: > f`, `cp /dev/null f`, `mv f /dev/null`, `xargs rm`), and the Pikkumies tool verbs that carry `--with-data`, `--expect` or `--replace`. A command longer than 4000 characters is blocked instead, because the review must see all of it.
- **A question for the ask policy, not about a delete**: exposure (a web server, web shell or tunnel on a network address: `python3 -m http.server`, `php -S 0.0.0.0:…`, ttyd, gotty, ngrok, cloudflared; rclone remote control without a password; a container engine API on `tcp://`; a container port published on every interface, `--network host`, `--privileged`, mounts of a socket, `~/.ssh`, the home or `~/pikkumies`, `rclone serve` off loopback), stopping every container (`pkill` / `kill` / `systemctl stop` of the Docker daemon), and load (`performance heavy`, raw benchmarks such as fio, iperf3 or stress-ng, and a drive self-test through `drives selftest`). The message names which of the three it is; load questions carry a `pikkumies-load:` rule_key (ADR-0020 amendment, [ADR-0034](../../../../docs/adr/0034-containers-category.md), [ADR-0035](../../../../docs/adr/0035-performance-diagnostics.md)).
- **Raw disk and md RAID commands** (`GuardDisk.php`, [ADR-0095](../../../../docs/adr/0095-md-raid-build-recover-and-tune-through-one-tool.md)): blocked, and the message names the mdraid tool (`tools/server-admin/mdraid/`), which does the same after checking the live device state. `mdadm` is read word by word, the mode found the way mdadm finds it (a device first or a first manage option is manage mode, so `-f` is `--fail` there, `--force` in assemble and misc, `--daemonise` in monitor; long options also as unique prefixes): create, build, grow, incremental, zero-superblock, assume-clean, write-zeroes, every manage operation (add, re-add, fail, remove, replace, ...), `--force`, `--run`, `--update`, `--readwrite`, `--action` other than `idle`, and any option it cannot check. Reads (`--detail`, `--examine`, `--query`, `--examine-badblocks`), `--stop`, `--readonly`, a plain `--assemble` and `--monitor` run. Also the formatters the mkfs rule misses (`mke2fs`, `mkntfs`, `mkdosfs`, `mkexfatfs`, `mkreiserfs`, `mkudffs`, `make-bcache`, `bcachefs format`, `zpool create|labelclear`), the partitioners the fdisk rule misses (`sfdisk`, `cfdisk`, `gdisk`, `cgdisk`; their list and dump options run), `cryptsetup luksFormat|erase`, `pvcreate`, a write to a disk's `/device/delete`, filesystem repair without `-n` (`e2fsck`, `fsck`, `fsck.*`, `dosfsck`, `xfs_repair`; `fsck -N` runs), and a write into `/sys/block/mdN/` or `/sys/dev/block/9:N/` (a redirect, `tee`, `of=` or a write call in code next to such a path in one part of the command, or a `cd` there and a relative attribute name), except `check` and `idle` written to `sync_action`, the scrub the drives guard allows. One owner per command: raw drive writes and drive tooling (`badblocks -w`, `hdparm` writes, `blkdiscard`, `mkswap` on a device, NVMe and SCSI format or sanitize, output written onto a device, `repair` written to a `sync_action`) are the drives guard's and name the drives tool; mdadm syntax, `mdadm --action=repair` included, is this rule's and names mdraid.
- **Blocked for privacy**: reading other accounts' cgroups, process lists or connections on a shared server, including a system unit's `systemctl status`, its `systemctl show` of `ControlGroup` or `MainPID` (or a bare `show`) and `GetUnitProcesses` over D-Bus, which PID 1 answers past /proc's hidepid=2 with other accounts' process titles. The account's own units (`--user`), `is-active`, `is-enabled` and root's own use (euid 0, or through `sudo`) are allowed. The message names no path.
- **Blocked like stored passwords**: `~/.docker/config.json` reads, `docker login` with a password on the command line, and any command on the AI key (`~/.virsilipasKey`, `~/.pikkumiesKey`, the Hermes `.env`, a `vsk-` key). The key files are also refused when a glob would expand to one (`cat ~/.v*Key`), when a relative path reaches one after a `cd` or from the call's working folder (`cd ~/pikkumies/local/hermes-managed && cat .env`), and in a content search from the home folder itself unless it excludes every key file name (`grep -rh ^key= ~`), `GuardKeyFiles.php`. The balance comes from `credits balance`; on Pulsed Media the key file is put in place for the user, and for their own provider the user writes `~/.pikkumiesKey` themselves.
- **Hermes file tools** (`read_file`, `write_file`, `patch`, `search_files`): only the path, the search pattern and each file a V4A patch names in its headers (`*** Update File:`, `Add File:`, `Delete File:`, both sides of `Move File: a -> b`) are checked, and only against the stored-password and AI-key rules, which block. Nothing else about a file tool is asked.
- **Backups to another machine** (`backup remote`, [ADR-0049](../../../../docs/adr/0049-backup-remote-over-ssh.md)): `setup`, `schedule`, a `PIKKUMIES_REMOTE_PASSWORD=` prefix or `--daily` is a send question for the ask policy (`rule_key` `pikkumies-send:`): it runs only when what the user asked for covers where the account's files go from then on. `php ... passphrase` is blocked: the backup passphrase is shown only on the user's own terminal. So is any command that names `remote.php` and also holds `$`, a backtick or `eval` (`V=passphrase; php remote.php $V`), except inside a single-quoted login value. This cannot stop every indirection (reading the pass file through an interpreter is out of its sight): the passphrase's real protection is that it exists only to be copied by the user once, and the archives are only as safe as this account.
- **Scheduled script jobs**: a `cronjob_manage` call that sets a script, a monitor or no-agent mode is a question for the ask policy (`rule_key` `pikkumies-schedule:`), because that script later runs by itself with no guard.
- **What the user asked for a scheduled job** (`lib/CronAuth.php`, [ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md)): a `cronjob_manage` `create` or `update` that carries a `prompt`, in a session with the user's words (the halt snapshot's evidence; none in an agent started by an agent), gets one ask review: did the user ask for this scheduled job (R1 yes, R3 no). Only then are their words kept for that prompt in `local/state/ask/jobs.json` (directory `0700`, file `0600`, written through a temporary name and a rename under a lock, at most 200 entries, newest kept), so the job's runs get the same safety check against what the user asked when it was made (`hooks/halt/halt-snapshot/`). The record step never blocks the call; the hook log gets a reason code only (`cron-auth-record`: `recorded`, `not-covered`, `no-answer`, `no-evidence`, `too-long`, `write-failed`, `error`), never the words or the prompt. A safety record at the same trust level as the halt snapshot, not a security boundary.
- **Another agent with its safety layers off** (ADR-0020 amendment 2026-10-18, `lib/NestedAgent.php`): blocked when a command starts `pikkumies run`, `hermes` or `hermes_cli` (a plain `pikkumies <words>` is a prompt and is not read) with `--yolo`, `--safe-mode`, `--ignore-rules`, `--ignore-user-config`, `--accept-hooks`, `--profile` or `-p` (also abbreviated, quoted, in list form or after `env -i`), with `-z` anywhere (`-zgo` too), or with `--oneshot` before the subcommand, read the way Hermes reads it (`-m chat --oneshot` is still top-level; `chat --oneshot` only answers and exits); `profile use`; `config set approvals.…` or the dotted `approvals.mode` spelling (a `sed` or `printf` edit of `config.yaml` is not caught); `/yolo` (this session) or `/approvals off|smart` (the whole profile) typed into a session; and a command that sets `HERMES_YOLO_MODE`, `HERMES_SAFE_MODE`, `HERMES_IGNORE_RULES`, `HERMES_IGNORE_USER_CONFIG` or `HERMES_ACCEPT_HOOKS`, or sets or removes `HERMES_HOME` or `PIKKUMIES_DEPTH` (reading them is fine). The launcher exports `PIKKUMIES_DEPTH` (its depth + 1); in an agent at depth 2 or more every question below becomes a block, yolo or not, because what the user asked for cannot be checked there (its "user" messages were written by the parent agent); the block is reported as a skipped step, and `pikkumies run` at depth 1 or more refuses the same flags and commands. The user's own runs are untouched.
- **Email** ([ADR-0053](../../../../docs/adr/0053-email-category.md), `GuardMail.php`): any email `login` is blocked (the user types logins in their own terminal); an smtp command with shell expansion, chaining or redirects (`$`, backtick, `*`, `?`, `[`, `{`, `~`, `;`, `|`, `&`, `<`, `>`, `\`, a line break) outside single quotes is blocked; `smtp send-draft <sha256>` is a mail question for the ask policy with what the draft holds (From, every recipient, Subject, each attachment path and size, the first 1 KiB of the body; `rule_key` `pikkumies-mail:<sha256>`), and a missing or changed draft is blocked; `smtp test` is a mail question too; imap and pop `delete` are delete questions.
- **Local hooks and notes** ([ADR-0054](../../../../docs/adr/0054-tool-hooks-and-local-hooks.md), `GuardLocal.php`): a write that can reach `~/pikkumies/local/hooks/`, `local/tools/` or `local/state/local-changes.json` is a question for the ask policy (`rule_key` `pikkumies-local:`): `write_file` and `patch` with the path and the first 600 characters of the text; a command that writes (`>`, `cp`, `mv`, `tar`, `rsync`, `ln`, `tee`, `mkdir`, `sed -i`, `open(` ...) and names such a path, names `pikkumies/local` itself as the target, has a glob or brace right after `pikkumies/` or `local/`, or cds into `pikkumies/local` (or into `pikkumies/` and names `local/...`, or below `pikkumies/` and names `../local`), with the whole command; every path is also read with `/./` and `seg/../` folded away. Reading is no question; `/usr/local/tools` is no question. Out of its sight: a relative path after a cd it did not see, a glob or variable before `pikkumies/`, a path built in code, a program writing without one of those words. It catches mistakes and naive steering, not self-modification; a local hook it missed still runs only from the next start.
- **The media apps' logins** (`GuardMediaCreds.php`, [ADR-0078](../../../../docs/adr/0078-changing-the-login-of-the-users-own-apps.md)): blocked when a command, code or file tool call names `~/.media-stack-credentials.txt`, holds a glob that expands to it (each word with `*`, `?`, `[` or `{`, unquoted, or quoted when it starts with `~`, `/` or `$HOME`; `~`, `$HOME` and a `cd` in the same command resolved, the folder part expanded with `glob()` and at most 256 folders, a wider one blocked), or searches content recursively from the home folder itself (`grep -r`/`-R`, `rg`, `ag`, `ack`, `ugrep -r`, `find ~ ... -exec`/`xargs` with a reader, `search_files` on content with path `~`, `$HOME`, the home path, or `.` when the payload's cwd is the home folder) unless an exclude option covers the file (`grep --exclude`, `ag --ignore`, `rg -g '!...'`, `find ! -name`). A search rooted at a subfolder runs. The login verbs read the file in their own PHP and never name it, so they pass; the agent tells the user where the file is. Out of its sight: a name or path built in a variable (`${f}`, `$(...)`), in code from pieces, or read by a program that is not one of those readers; a `cd` made in an earlier call.
- **Package removal**: `apt`, `apt-get` or `aptitude` `remove`, `purge`, `autoremove` or `autopurge`, and `dpkg -r` / `-P`, are asked as a delete (an install is not) ([ADR-0099](../../../../docs/adr/0099-backup-safety-layer.md)).
- **Backups first** (`GuardBackup.php`, ADR-0099): before any delete question it reads the backup status cache that `backup-safety` keeps (`local/state/backup-status.json`, never running a backup tool) and holds the agent once with a block, never the user: a plain removal (`rm`, `unlink`, `shred`, `truncate`, `: >`, package removal) while no backup is known to work is told to copy the targets first with `backup-safety snap` (the exact command) and to suggest a storage box with the addresses from the documentation sources; a dangerous delete (`rm -r`, package removal, and every other delete rule) is told to show the user the table of the 10 latest backups first. The identical command in the same session within 30 minutes, or a removal whose every target was snapped in the last 30 minutes, then reaches the question as before. Files only in `/tmp`, `/var/tmp` or `/dev/shm` outside the home, a call without a session id, and an append, install or copy are never held. A delete question adds `Latest backup: <age>, <size> (<kind>).` when that still fits the panel.
- **Every question carries a `kind`** (`delete`, `exposure`, `stop`, `load`, `send`, `schedule`, `mail`, `local`). The orchestrator's ask policy reads it ([ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md)): `stop` and `load` run without a review, and the others go to the ask review, which lets the call run unless it may lose or reveal data for good beyond what the user asked for; then the call is refused and the agent reports it as skipped, never asks ([ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md)). Hermes never sees the kind.
- Anything else: no answer, and the call runs.

It fails closed: when it cannot answer, or cannot read the tool call it was given, the call is blocked. This is a safety prompt for the agent's own mistakes, not a security boundary; real limits come from the OS.

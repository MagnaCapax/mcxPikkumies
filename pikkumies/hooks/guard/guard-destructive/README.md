# guard-destructive

The delete guard ([ADR-0020](../../../../docs/adr/0020-deletes-need-the-users-approval.md)). Before each `terminal` or `execute_code` call, and each `process_manage` write or submit (text typed into a background shell), it checks the command:

- **Blocked** outright, with a message telling the agent not to reach the same effect another way, to finish the rest of the task and to say in one line what was refused: a recursive delete of a whole home folder written as `/home/<name>` (Hermes refuses the `~` and `$HOME` forms itself), filesystem formats, raw device writes, partition changes, world-writable permissions, fork bombs, force pushes, a delete verb renamed through an alias or a variable, base64-decoded text run by a shell, reading stored passwords (`local/secrets/`, `rclone config show|dump`), and any call that names the halt guard's state (`local/state/halt/`, file tools included: it holds the evidence the ask review trusts, [ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md)). Quotes and backslashes inside a word do not hide a verb (`r"m"` is `rm`).
- **Asks the user** (`approve`, with the whole command in the message and a `rule_key` of that exact command): deletes the user may want, such as backup prunes, `rclone sync|move|purge`, torrent removes with data, `*arr` and media server deletes, plain `rm` and `rm -rf` (Hermes itself still refuses a recursive delete of `/`, the home or system folders), emptying a file (`: > f`, `cp /dev/null f`, `mv f /dev/null`, `xargs rm`), and the Pikkumies tool verbs that carry `--with-data`, `--expect` or `--replace`. A command longer than 4000 characters is blocked instead, because the user must see all of it.
- **Asks the user, not about a delete**: exposure (a web server, web shell or tunnel on a network address: `python3 -m http.server`, `php -S 0.0.0.0:…`, ttyd, gotty, ngrok, cloudflared; rclone remote control without a password; a container engine API on `tcp://`; a container port published on every interface, `--network host`, `--privileged`, mounts of a socket, `~/.ssh`, the home or `~/pikkumies`, `rclone serve` off loopback), stopping every container (`pkill` / `kill` / `systemctl stop` of the Docker daemon), and load (`performance heavy` and raw benchmarks such as fio, iperf3 or stress-ng). The message names which of the three it is; load questions carry a `pikkumies-load:` rule_key (ADR-0020 amendment, [ADR-0034](../../../../docs/adr/0034-containers-category.md), [ADR-0035](../../../../docs/adr/0035-performance-diagnostics.md)).
- **Blocked for privacy**: reading other accounts' cgroups, process lists or connections on a shared server. The message names no path.
- **Blocked like stored passwords**: `~/.docker/config.json` reads, `docker login` with a password on the command line, and any command on the AI key (`~/.virsilipasKey`, `~/.pikkumiesKey`, the Hermes `.env`, a `vsk-` key). The balance comes from `credits balance`; the user edits key files in a terminal.
- **Hermes file tools** (`read_file`, `write_file`, `patch`, `search_files`): only the path, the search pattern and each file a V4A patch names in its headers (`*** Update File:`, `Add File:`, `Delete File:`, both sides of `Move File: a -> b`) are checked, and only against the stored-password and AI-key rules, which block. Nothing else about a file tool is asked.
- **Backups to another machine** (`backup remote`, [ADR-0049](../../../../docs/adr/0049-backup-remote-over-ssh.md)): `setup`, `schedule`, a `PIKKUMIES_REMOTE_PASSWORD=` prefix or `--daily` asks the user (`rule_key` `pikkumies-send:`), because they decide where the account's files go from then on. `php ... passphrase` is blocked: the backup passphrase is shown only on the user's own terminal. So is any command that names `remote.php` and also holds `$`, a backtick or `eval` (`V=passphrase; php remote.php $V`), except inside a single-quoted login value. This cannot stop every indirection (reading the pass file through an interpreter is out of its sight): the passphrase's real protection is that it exists only to be copied by the user once, and the archives are only as safe as this account.
- **Scheduled script jobs**: a `cronjob_manage` call that sets a script, a monitor or no-agent mode asks the user (`rule_key` `pikkumies-schedule:`), because that script later runs by itself with no guard and nobody to ask.
- **Another agent with its safety layers off** (ADR-0020 amendment 2026-10-18, `lib/NestedAgent.php`): blocked when a command starts `pikkumies run`, `hermes` or `hermes_cli` (a plain `pikkumies <words>` is a prompt and is not read) with `--yolo`, `--safe-mode`, `--ignore-rules`, `--ignore-user-config`, `--accept-hooks`, `--profile` or `-p` (also abbreviated, quoted, in list form or after `env -i`), with `-z` anywhere (`-zgo` too), or with `--oneshot` before the subcommand, read the way Hermes reads it (`-m chat --oneshot` is still top-level; `chat --oneshot` only answers and exits); `profile use`; `config set approvals.…` or the dotted `approvals.mode` spelling (a `sed` or `printf` edit of `config.yaml` is not caught); `/yolo` (this session) or `/approvals off|smart` (the whole profile) typed into a session; and a command that sets `HERMES_YOLO_MODE`, `HERMES_SAFE_MODE`, `HERMES_IGNORE_RULES`, `HERMES_IGNORE_USER_CONFIG` or `HERMES_ACCEPT_HOOKS`, or sets or removes `HERMES_HOME` or `PIKKUMIES_DEPTH` (reading them is fine). The launcher exports `PIKKUMIES_DEPTH` (its depth + 1); in an agent at depth 2 or more every question below becomes a block, yolo or not, because the one answering would be the parent agent, and `pikkumies run` at depth 1 or more refuses the same flags and commands. The user's own runs are untouched.
- **Email** ([ADR-0053](../../../../docs/adr/0053-email-category.md), `GuardMail.php`): any email `login` is blocked (the user types logins in their own terminal); an smtp command with shell expansion, chaining or redirects (`$`, backtick, `*`, `?`, `[`, `{`, `~`, `;`, `|`, `&`, `<`, `>`, `\`, a line break) outside single quotes is blocked; `smtp send-draft <sha256>` asks with what the draft holds (From, every recipient, Subject, each attachment path and size, the first 1 KiB of the body; `rule_key` `pikkumies-mail:<sha256>`), and a missing or changed draft is blocked; `smtp test` asks; imap and pop `delete` ask as deletes.
- **Local hooks and notes** ([ADR-0054](../../../../docs/adr/0054-tool-hooks-and-local-hooks.md), `GuardLocal.php`): a write that can reach `~/pikkumies/local/hooks/`, `local/tools/` or `local/state/local-changes.json` asks the user (`rule_key` `pikkumies-local:`): `write_file` and `patch` with the path and the first 600 characters of the text; a command that writes (`>`, `cp`, `mv`, `tar`, `rsync`, `ln`, `tee`, `mkdir`, `sed -i`, `open(` ...) and names such a path, names `pikkumies/local` itself as the target, has a glob or brace right after `pikkumies/` or `local/`, or cds into `pikkumies/local` (or into `pikkumies/` and names `local/...`, or below `pikkumies/` and names `../local`), with the whole command; every path is also read with `/./` and `seg/../` folded away. Reading is not asked; `/usr/local/tools` is not asked. Out of its sight: a relative path after a cd it did not see, a glob or variable before `pikkumies/`, a path built in code, a program writing without one of those words. It catches mistakes and naive steering, not self-modification; a local hook it missed still runs only from the next start.
- **Every question carries a `kind`** (`delete`, `exposure`, `stop`, `load`, `send`, `schedule`, `mail`, `local`). The orchestrator's ask policy reads it ([ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md)): `stop` and `load` run without a question, and the others go to the ask review, which lets the call run unless it may lose or reveal data for good beyond what the user asked for. Hermes never sees the kind.
- Anything else: no answer, and the call runs.

It fails closed: when it cannot answer, or cannot read the tool call it was given, the call is blocked. This is a safety prompt for the agent's own mistakes, not a security boundary; real limits come from the OS.

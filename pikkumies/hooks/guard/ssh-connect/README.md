# ssh-connect

Before the agent connects to another machine over SSH, it says why, and the person's lists decide where ([ADR-0068](../../../../docs/adr/0068-ssh-connections-need-a-stated-intent-and-the-persons-allow-and-deny-lists.md); the user guide is [docs/ssh.md](../../../../docs/ssh.md)).

- **Intent.** A connection needs `# intent: <why, in a few words>` (at least 8 characters) in the command, or one stated for that host earlier in the same session. The reason is kept in `local/state/ssh-intent/<sha1 of session id NUL host>` (directory 0700, file 0600, files older than 7 days removed on the next write) and only saves repeating it: it never allows, refuses or asks anything, so writing one by hand gains nothing. No valid session id (`^[A-Za-z0-9._-]{1,128}$`): the reason must be in every command.
- **Lists.** `ssh.deny` is refused, through any name the connection uses: the host typed, `-o HostName` (with `%h`), every `-J`/ProxyJump/`-W` hop, the ssh hop of a ProxyCommand, and a host in the remote command (`ssh nas 'ssh other'`). Every name on `ssh.allow`: no question. Anything else, and a route this check cannot follow (`-F <file>`, `-S`, ControlPath, a ProxyCommand without an ssh hop, `rsync -e` or `mosh --ssh` naming another program, `GIT_SSH_COMMAND`, `GIT_SSH`, `RSYNC_RSH`, `core.sshCommand`), gets Hermes' approval prompt; with `ssh.blockUnknown` on it is refused instead. Entries are host names, addresses or patterns with `*` and `?`, matched against the whole name (`lib/SshLists.php`); on the allow list an address pattern matches only an address. The lists are read from `local/config.php` without the `PIKKUMIES_CONFIG` overlay.
- **The question** names the hosts, the routes and the agent's reason before the command, and is keyed `pikkumies-ssh:<sha1 of the command>`, so an "always" answer covers that exact command and never becomes a second, hidden allow list. A question longer than Hermes' approval panel surely shows (`HookUnits::approveShown()`, 350 characters) is refused instead: shorten the command or the reason, or allow the host. Next to another check's question (a delete with `rsync --delete`) the two together are usually too long and the call is refused naming both; allowing the host leaves only the delete question. In an agent started by an agent every question is a block, and cron and one-shot runs refuse questions: hosts for scheduled jobs belong on `ssh.allow`.
- **What it reads.** `terminal` commands and `process_manage` input: ssh, autossh, mosh, sftp, scp, rsync, sshfs, ssh-copy-id, ssh-keyscan and git with an SSH remote, at command position, behind sudo, env, timeout, nice, nohup, xargs, sshpass and similar wrappers, inside `sh -c`, `su -c`, `eval`, `watch`, `$(...)` and backticks, and anywhere in text piped or here-string'd into a shell. A host it cannot read for certain is refused: a variable, substitution, glob or brace in it, an ssh option letter OpenSSH 10.0 does not list, a numeric address that is not a plain dotted quad (`3232235777`, `127.1`), a program stored in a variable or alias. SSH from `execute_code` is refused (run it from the terminal). A command it would show in a question is refused when it holds control or direction characters (a trailing intent is shown cleaned instead), and a command over 100000 characters is refused. Writes to `~/.ssh/config` and `~/.ssh/config.d/` (file tools, V4A patch headers, a shell write) are asked, because that file decides where a host name really connects.
- **Fails closed**: a crash, a timeout, a regex engine error or a payload it cannot read blocks the call.

It is a safety prompt for the agent's mistakes and for text that tries to steer it, not a security boundary: the agent runs as the same user and can edit `local/config.php`, and a script or program that connects by itself (`./sync.sh`, `make deploy`, ansible), a git remote stored in the repository, an alias from `~/.bashrc`, an `Include` outside `~/.ssh`, a name that resolves to a denied address, forwards through an allowed host, the rsync daemon and raw TCP are out of its sight. The limit that holds whatever the agent types is on the other machine: `from="<this server>",restrict` on the key in its `authorized_keys`, as `backup remote` does.

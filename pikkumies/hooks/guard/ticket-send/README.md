# ticket-send

Holds `/ticket` until the user's own request covers it ([ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md), [ADR-0089](../../../../docs/adr/0089-support-tickets-with-the-ai-key.md), [ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md)). Before `ticket send <id>` runs, the orchestrator's ask policy checks it: the question says that a support ticket goes to Pulsed Media at pulsedmedia.com, opened with the user's AI key, from which account email, for which service, at which priority, with which files and their sizes; then the file holding all of it, and the subject and how the message starts. It is reviewed as a send, so only what the user asked for in their own words clears it (R1 yes, R3 no); otherwise it is refused and the agent reports it as skipped, never asks. Where the user's words cannot be checked (a scheduled job made without them, an agent started by an agent) the send stays refused.

In an agent started by another agent the person's own request cannot be checked, so this hook blocks the send and the agent reports it as skipped, without the command. Under `--yolo`, the default run mode, the send is reviewed like any other.

Only the plain command `php <path>/tools/system/ticket/ticket.php send <id>`, on its own, with the absolute (or `~/`) path of this Pikkumies' own tool, goes to the ask policy. The other forms it can see are blocked: a send chained with other commands, run from code or a background process, written into a file or a scheduled job, built with shell expansion, or of a draft that is missing, changed or already sent.

It is the same check as [feedback-send](../feedback-send/README.md) (`lib/SendGuard.php`). It catches the agent's own and casual sends. It is a safety prompt, not a security boundary: an agent steered by text it reads runs as the same user and can still run the sender some other way, as it could run curl.

One exception ([ADR-0100](../../../../docs/adr/0100-ticket-bundle-diagnostics-and-automatic-tickets-on-pulsed-media-servers.md)): a ticket the agent bundled by itself (`ticket bundle --by agent`) goes out without a question while `ticket.auto` is on. Unset, that is on on a Pulsed Media server and off elsewhere; the person turns it off with the pikkumies-configure skill. It must carry this account's processes and files only, and its files must be what `bundle` made; the tool's caps (2 such tickets in 24 hours, never the same subject twice) bound it.

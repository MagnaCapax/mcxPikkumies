---
name: ticket-send
event: pre_tool_call
description: Holds a /ticket send until the user says yes in the chat (the ask policy, ADR-0073); an agent bundle runs while ticket.auto is on; blocked under --yolo or in an agent started by an agent; other forms of a ticket send are blocked.
failClosed: true
timeout: 3
---
The same check as `guard/feedback-send`, in `lib/SendGuard.php` ([ADR-0089](../../../../docs/adr/0089-support-tickets-with-the-ai-key.md)). A terminal command that is exactly `php <this Pikkumies' ticket.php> send <id>`, the path absolute (or `~/`, expanded with HOME) and canonical, gets `approve` with `rule_key` `pikkumies-send:<id>`, which the orchestrator's ask policy turns into a block until the review finds the user's own yes in the chat, and a block outright where no yes can be checked ([ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md)). The message (`tools/system/ticket/TicketPrompt.php`) opens with where it goes and from which account email, then the service, priority, attached files with their sizes, the file holding all of it, and last the subject and the start of the message on one line with quotes escaped; the whole message passes `HookUnits::approveShown()`, and one that cannot fit is a block. With `HERMES_YOLO_MODE` set (--yolo) or at `PIKKUMIES_DEPTH` 2 or more, the plain send is blocked and the message gives the command for the user to run in their own terminal. Blocked, in a terminal command, `execute_code` code, `process_manage` input, `write_file` or `patch` content and `cronjob_manage` input: a ticket path followed by `send` (only the word right after the path counts), `TicketSend` or `TicketDraft` with the word send, and a ticket path with shell expansion (`$ * ? [` or a backtick) and the word send. Also blocked: a draft that is missing, changed since it was made, or already sent. One exception ([ADR-0100](../../../../docs/adr/0100-ticket-bundle-diagnostics-and-automatic-tickets-on-pulsed-media-servers.md)): a draft made by `ticket bundle --by agent` while `ticket.auto` was on (scrubbed, its message saying the holder has not seen it), collected without root for this account only (`process_scope`, `privilege`: self-asserted by the bundle record), whose files pass `TicketAuto::checkFiles` with the automatic-ticket pass, runs without a question, never when this hook runs as root, while `ticket.auto` is on (unset: on on a Pulsed Media server, off elsewhere; read from `local/config.php`, never the overlay), also under --yolo or unattended; the tool's own caps bound those. A bundle draft whose files are not what `bundle` makes is blocked. A safety prompt that catches the agent's own and casual sends, not a security boundary: an agent steered by text it reads can still run the sender some other way, as it could run curl (AGENTS.md).

# publish-check

The check before publishing ([ADR-0083](../../../../docs/adr/0083-check-before-publishing.md)). When the agent pushes, opens an issue or a pull request, comments, makes a release or a gist for you in a public place, it first reads what would go out. A password, an API key, a token or a private key published there stays readable to everyone, also after it is deleted, so it has to be caught before.

- **What is a public place:** a repository on github.com, gitlab.com, codeberg.org or bitbucket.org that is not private, and every gist (a "secret" gist is readable by anyone who has its link). Whether a GitHub repository is private is asked with `gh repo view`; when that gives no answer (gh missing or logged out, no network, GitLab and the others), it counts as public. Your private repository is your own space and is not read. A push to any other remote (your own servers, a self-hosted git server, another folder) is never looked at, and neither are ssh, scp and rsync.
- **What is read:** for a push, the commits the remote does not have yet: their messages, every added line, and the names of the files they add. For a remote that has nothing yet, everything the push sends. For gh, the title, body and notes and the files it publishes (a body file, gist files, release assets). At most 4 seconds; what was not read is said, never counted as clean.
- **What counts:** what Pikkumies' redactor removes from logs and `/feedback` (`lib/Redact.php`): option, header, variable and config-file forms of passwords and keys, private key blocks and the common token forms. And files named like a credential file: `.env` (not `.env.example`), `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa` and the other private SSH keys, `credentials`, `.netrc`. Code that only names a password variable can count too; then the second run goes to the review.
- **What happens:** the call is not run. The agent gets the lines with the values masked, takes the value out itself (rewrites the commit, moves it to a file that is not tracked) and publishes again, which is checked again. When it is meant to be public, the agent runs the same command again: it is then reviewed as a send and runs only when what you asked for covers publishing it, and is otherwise refused and reported in the answer, never asked ([ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md), [ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md)). In a session where your words cannot be checked (a scheduled job made without them, an agent started by an agent), it stays blocked while it still holds those lines, and the answer lists it as skipped.
- **Out of its sight:** a push run from code, a script or an alias, `gh api`, a body typed in an editor or the browser (`--editor`, `--web`), a branch `gh pr create` pushes by itself, other people's personal data (names, addresses: the agent's own rule in `safety.md` covers those), and a private repository you plan to make public: say so, and the agent treats it as public.

A safety prompt for the agent's own mistakes, not a security boundary (AGENTS.md).

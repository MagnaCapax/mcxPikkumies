# fileops-check

A second look before the agent changes permissions, owners, attributes or names in bulk, and a quick list of what was there first ([ADR-0048](../../../../docs/adr/0048-fileops-check-recheck-and-file-list.md)). It runs on `pre_tool_call` for `terminal` commands and `execute_code` code, next to [guard-destructive](../guard-destructive/README.md), which keeps doing its own job unchanged.

- **Blocked once, for the agent to re-check:** recursive `chmod`, `chown` and `chgrp`, the same run by `xargs`, `find ... -exec` or `-execdir` of `chmod`, `chown`, `chgrp` or `mv`, `chattr`, `rename` and `setfacl`. The message says how many entries the targets hold (or "over 50000"), which of the home itself, `~/.ssh` and the pikkumies directory the targets are or hold, and where the list is, and tells the agent to say in its answer in one line what the command changes and run the identical command again, or change the command. Running the identical command again in the same session within 10 minutes proceeds (marker `local/state/fileops/<sha1 of session id NUL command>`). Without a valid session id, or when the marker cannot be written, it becomes a question for the orchestrator's ask policy instead, which lets it run unless the review finds it irreversible and not asked for ([ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md)).
- **A question for the ask policy** (`approve`, the safety check runs it or refuses it and the refusal is reported, [ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md); the whole command in the message, `rule_key` `pikkumies-fileops:` and a hash of the command): `mv` onto an existing file under the home, or several sources landing on one name; a recursive permission, owner, ACL or attribute change of the home itself, `~/.ssh` or the pikkumies directory (or a directory holding them); targets holding more than 50000 entries. This tier never looks at the marker, and a command too long to show in full (4000 characters) is blocked instead.
- **Silent:** a plain `chmod`, `chown` or `chgrp` of named files, `mv` to a new name or into a directory without a clash, `mv -n`, and everything else.

**The list.** Before any answer (also before a re-run that passes) it writes `local/logs/fileops/<sha1 of the tool call id>.jsonl.gz` (dir 0700, file 0600): a first line `{"ts","session_id","tool_call_id","command","targets","truncated"}`, then one line per entry `{"p","t","m","u","g","s","mt"}` (path, type `f`/`d`/`l`/`o`, octal mode, owner and group ids, size, modification time), plus `"a"` with the `lsattr` flags when the command is `chattr` or there are at most 200 entries. Check a mistake with `zcat <file> | jq -c 'select(.p) | [.p, .m, .u, .g]'`.
- Relative paths are resolved against the call's `workdir`; without one, nothing is listed and the message asks for absolute paths. Globs are expanded one path component at a time with `opendir` and `fnmatch`, within the same limits as the walk.
- Only paths under the real home are listed. Symlinks are listed, never followed. The walk stops after 2 seconds or 50000 entries (`truncated: true`).
- A command with a pipe, `;`, `&&`, a variable, a substitution or `xargs`, and any `execute_code` code, is still classified, but its targets are recorded as `not captured`: a `cd` or a variable makes the paths in the text unreliable. For the same reason such an `mv` is not checked for an existing target.
- Extended attributes are `lsattr` flags only: PMSS has no `getfattr` or `getfacl`, and PHP reads no extended attributes.
- Kept for `sessions.retentionDays` (0 = keep), and the directory is held under 50 MiB by removing the oldest lists.

It fails open (5 s): a walk that runs out of time or a crash lets the command run, and the delete guard still checks it. Off with `fileopsCheck.disabled` in `local/config.php`. A safety prompt for the agent's own mistakes, not a security boundary (AGENTS.md).

# feedback-send

Holds `/feedback` until the user's own request covers it ([ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md), [ADR-0056](../../../../docs/adr/0056-feedback-what-pikkumies-sends-to-pulsed-media.md), [ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md)). Before `feedback send <id>` runs, the orchestrator's ask policy checks it: the question opens with where it goes and what goes: the user's text, the conversation transcript (all of it, its newest 1.5 MB, or none) and system information, to Pulsed Media at pikkumies.mcx.fi, locked and linked to their account; then the size, the file holding all of it and how the text starts. It fits what the ask review can show in full on the model's own turn. It is reviewed as a send, so only what the user asked for in their own words clears it (R1 yes, R3 no); otherwise it is refused and the agent reports it as skipped, never asks. Where the user's words cannot be checked (a scheduled job made without them, an agent started by an agent) the send stays refused.

In an agent started by another agent the person's own request cannot be checked, so this hook blocks the send and the agent reports it as skipped, without the command. Under `--yolo`, the default run mode, the send is reviewed like any other.

Only the plain command `php <path>/tools/system/feedback/feedback.php send <id>`, on its own, with the absolute (or `~/`) path of this Pikkumies' own tool, goes to the ask policy. The other forms it can see are blocked: a send chained with other commands, run from code or a background process, written into a file or a scheduled job, built with shell expansion, or of a draft that is missing, changed or already sent.

This catches the agent's own and casual sends. It is a safety prompt, not a security boundary: an agent steered by text it reads (a web page, a torrent name) runs as the same user and can still run the sender some other way, as it could run curl. What it sends is sealed to Pulsed Media either way.

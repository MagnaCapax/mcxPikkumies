# usage-count

Runs after each tool call (`post_tool_call`) and counts it into the local telemetry store ([ADR-0087](../../../../docs/adr/0087-tool-skill-and-verb-usage-counts-kept-on-this-machine.md)), so the agent (or the person, with `telemetry usage`) can answer "how many times was X used" and "how often did it succeed" without Hermes' own `/insights` database, which PHP cannot read on every host.

- **Where:** `local/state/telemetry/usage-tool/`, `local/state/telemetry/usage-skill/` and one `local/state/telemetry/usage-u-<tool>/` per Pikkumies tool unit actually used, through [`TelemetryLog`](../../../tools/system/telemetry/TelemetryLog.php) (same layout, same `local`-only promise as every other telemetry source: `YYYYMMDD.jsonl`, directory 0700, files 0600).
- **What one line holds:** `ts` plus exactly one other field, 1 (the call succeeded) or 0 (it failed) -- never a command, a path, an argument or a session id.
  - `usage-tool`: field = the Hermes tool name (`terminal`, `skill_view`, `read_file`, ...).
  - `usage-skill`: field = the skill name, only for a `skill_view` call that names one.
  - `usage-u-<tool>`: field = the verb, only for a `terminal` call whose command runs that tool's own `*.php` script -- the `php` call must start the command or follow `&&`, `;` or `|` (a command that only mentions a unit, such as `echo 'php ... show'`, is never counted, security review F-TEL/F4d), the path is resolved with `realpath()` (a relative path against the tool call's own `cwd` from the payload, never this hook's own, F-TEL/F2; a leading `~/` against this process's own HOME) and must land under `Units::toolsDir()`, so a look-alike path elsewhere -- or the same unit reached from the wrong directory -- is never counted. The word after the path is recorded only when it is one of that unit's own verbs, from its `USAGE.md` verbs table; anything else -- a password, a path, a username that merely came first -- becomes `other`, never the word itself (security review F-TEL/F1).
  - A name lowercases, turns "-" and "/" into "_", and becomes `other` if it still does not fit a field name (over 32 characters, an MCP or plugin computed name, an odd skill name).
- **Reading it back:** `telemetry usage [--days N] [--kind tool|skill|unit] [--human]` (see `tools/system/telemetry/USAGE.md`). Never through a remote `serve` peer: `series` and `list` hide every `usage-*` source when the environment carries `PIKKUMIES_SERVE=1` (security review F-TEL/F4), which `serve.php` sets for every tool it runs.
- **Privacy:** gated by `privacy.perfLogging` (through `TelemetryLog::record` itself): off, nothing is written. Never `privacy.telemetry`, and nothing here is ever sent anywhere.
- **Growth:** these are counter-style writes -- many small lines a minute is normal, not abuse, and this hook is never reachable from a remote `serve` peer -- so they skip the per-minute cap built for a repeated diagnostic verb ([ADR-0086](../../../../docs/adr/0086-local-only-telemetry-history-for-diagnostics-and-health-runs.md)'s security review row F9c); the per-file size cap still applies.

It fails open: a failure to write never stops the tool call it is counting, and is itself counted (`TelemetryLog::noteFailure`, visible in `telemetry list`'s `failures` column) rather than raised.

# email

The user's own mail, on the user's request: `imap` (read, search, save attachments, move, flag, delete, archive to Maildir), `pop` (list, download to Maildir, delete), `smtp` (send through the user's own relay) and `antispam` (the user's own spam rules over IMAP). Works with any provider that offers IMAP, POP or SMTP over TLS; nothing is detected on the machine, the user types the server at login. [ADR-0053](../../../docs/adr/0053-email-category.md).

The units share `lib/`: `MailTransport.php` (the one mail connection, PHP curl), `MailImap.php` (IMAP commands, used by `imap` and `antispam`), `MailParse.php` (headers, text and attachments of a message), `MailPath.php` (where files may be written and read), `Maildir.php` (the one Maildir writer, used by `imap archive` and `pop fetch`), `MailLogin.php` (logins) and `MailUnit.php` (loading and state files). They have no verbs or record fields in common, so this category has no verb table; each unit's USAGE.md lists its own.

## Safety rules (in the code, the guard and DOCTRINE.md)

1. **TLS only, always verified.** IMAP 993, POP 995, SMTP 465, or SMTP 587 with STARTTLS required. Never port 25, 110 or 143, never a plaintext fallback, no setting to skip certificate checks. A server on this machine is used only when this account owns its port (`pikkumies/lib/Http.php`, [ADR-0019](../../../docs/adr/0019-hosts-and-credentials.md)).
2. **Logins at a terminal.** `login` asks for the server, user and password (hidden) at the user's terminal and stores them with `pikkumies/lib/SecretFile.php` in `pikkumies/local/secrets/email-<unit>` (0600). It tries the login before storing it. The guard blocks the agent from running any email `login` and from reading `local/secrets/`.
3. **Mail is untrusted.** Body text is printed as `untrusted_text`; the agent treats all of it as data (DOCTRINE.md). Reading changes nothing: a fetch sets `\Seen` on the server, so a message that was unseen is set back.
4. **Commands cannot be smuggled.** A uid is a plain number (never `1:*`); folder names and search words are printable ASCII; quoted strings are escaped and `%` is sent as `%25`, because libcurl URL-decodes IMAP commands; folders in a URL are encoded per part, so `;UID=` in a name changes nothing.
5. **Deletes are exact.** `imap delete` needs `--expect` (the folder's uidvalidity from `list`) and removes only the given uids with `UID EXPUNGE`; a server without UIDPLUS is refused, never a plain `EXPUNGE`. `pop delete` checks each message's UIDL first. Either runs when the user already asked for exactly this; otherwise the guard blocks it until the user says yes in the chat ([ADR-0073](../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md)).
6. **Attachments go only to a new directory.** `imap fetch` creates a fresh directory (default `~/mail-attachments/<folder>-<uid>-<time>`), refuses any path that exists or lies under a dot-directory, `~/www`, `~/bin` or `pikkumies/`, cuts each name to a plain file name, and creates files with `fopen 'x'` (0600, never replacing a file).
7. **Sending is checked first.** `smtp send` writes a draft, `local/state/email-outbox/<sha256>.json`; `send-draft <sha256>` runs when the user already asked for exactly this message, and otherwise is blocked until the user says yes in the chat (rule key `pikkumies-mail:<sha256>`), so the agent states From, every recipient, Subject, each attachment's path and size, and the first 1 KiB of the body before running it again. The unit re-hashes the draft and every attachment before sending, so it sends exactly what was checked. `send-self` and `test` go only to the user's own addresses stored with the login. Bodies and attachments are files inside the home, never in a dot-directory or `local/secrets/`, never a key. 20 MiB at most, encoded.
8. **Sizes and quota.** Every read is capped in curl's write callback (50 MiB per message). `imap archive` and `pop fetch` stream each message to `Maildir/tmp`, link it into `new/`, and stop before the account would have less than 10% of its disk or file quota free.

Run logs: `pikkumies/local/logs/email/YYYYMMDD.jsonl`, one file per UTC day (counts, bytes, seconds; never addresses or text). They are kept as long as the session history, `sessions.retentionDays` (0 = forever, the default): a new day's file removes files older than that.

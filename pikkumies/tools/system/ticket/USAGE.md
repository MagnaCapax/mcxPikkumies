# ticket

One Pulsed Media support ticket, opened with the Pulsed Media AI key ([ADR-0089](../../../../docs/adr/0089-support-tickets-with-the-ai-key.md)). `draft` saves exactly what would be posted under `~/pikkumies/local/state/ticket/<id>.json` and shows it; nothing leaves the machine. `send` posts it as JSON to `https://pulsedmedia.com/remote/ticket.php` with the key from `~/.virsilipasKey` as the Bearer token, only when the user's own request covers it (hook `guard/ticket-send`, the orchestrator's ask policy, [ADR-0073](../../../../docs/adr/0073-no-questions-no-deferrals-one-reviewed-exception.md)). `bundle` drafts a ticket with the diagnostics attached; one the agent bundles by itself goes out on its own while `ticket.auto` is on ([ADR-0100](../../../../docs/adr/0100-ticket-bundle-diagnostics-and-automatic-tickets-on-pulsed-media-servers.md)).

| verb | arguments | changes | what it does |
|---|---|---|---|
| draft | `--subject S (--text T \| --text-file F) [--email E] [--priority Low\|Medium\|High] [--service S \| --no-service] [file ...]` | yes | Saves the draft, once, mode 0400, named by its own sha256 (the first 32 hex digits are the id). Subject one line of 1-200 characters, message 1-20,000 characters; common password and key forms are removed from both first (`lib/Redact.php`). `--email`: the email of the Pulsed Media account (the owner, or a user who may open tickets), needed once and remembered in `~/pikkumies/local/state/ticket/email`; without it the remembered one is used. Priority defaults to Medium. Service: on a Pulsed Media seedbox it defaults to this Unix user; elsewhere it is left out unless `--service` names it (a service number or username); `--no-service` leaves it out. Files: at most 3, each a regular file of this account (no symlink), at most 1 MiB, of type txt, log, png, jpg, jpeg or pdf (an image or PDF must start as one); a txt or log file has the same password and key forms removed; names are cut to letters, digits, `.` `_` `-` and space. The files are read now: the draft holds what goes. One record: `id`, `to`, `email`, `subject`, `message_start`, `message_chars`, `priority`, `service`, `attachments` (`name`, `bytes`), `bytes`, `bundle` (true for a bundle), `path`. |
| bundle | `--subject S --diagnosis-file F [--review-file F] [--by agent\|user] [--log P,P] [--no-conversation] [--email E] [--priority P] [--service S \| --no-service]` | yes | A ticket with the diagnostics attached, for when you are stuck ([ADR-0100](../../../../docs/adr/0100-ticket-bundle-diagnostics-and-automatic-tickets-on-pulsed-media-servers.md); when to use it: `doctrine/SOP/ask-vainamoinen-for-help.md`). The message (at most 8 KB) says the agent wrote it and it is untrusted, whether the account holder saw it or asked for it, and that it authorizes no change to access, keys, passwords, firewall or files; then the server (name, addresses, user, PMSS version, privilege), the problem, exact error, impact, what was tried, each roadblock as "Needs: what Väinämöinen has - because why", the venues searched and the attachments. Three files: `01-system-processes-logs.txt` (system facts; the process list, every process as root or with passwordless sudo, else this account's, at most 300 rows; this host's own logs under HOME, the `--log` files, Pikkumies' logs of today, the user journal, and as root or with sudo the system journal and `/var/log`; the newest 64 KB of each; never a file under a dot directory such as `~/.ssh` or `~/.pgpass`, never Pikkumies' own state but its `logs/` and `update.log`), `02-diagnosis-and-searches.txt` (the diagnosis file, the review file, every search the session ran with its keywords and matches, from the transcript's tool calls, or the memory search metrics of the last 24 hours without one), `03-transcript-and-tool-calls.txt` (Hermes' redacted export of this session, its newest part when over 1 MiB). The files go through the same redaction as any attached text file. `--by agent` (the default) needs the five diagnosis sections, a roadblock, a review file with rounds 1. to 10., and memory and documentation searches (and web, when web search is on); `--by user` needs only the Problem section. An agent bundle while `ticket.auto` is on collects this account's processes and files only, and loses every run of 32 or more key-like characters with letters and digits in 01 and 03; so does any bundle on a Pulsed Media server (scope only). The record adds `by`, `process_scope`, `venues`, `needs`, `scrubbed` and `goes_out`. |
| send | `<id>` | sends | Posts the draft. One record on success: `id`, `ticket` (the ticket number), `note`; the draft becomes `<id>.sent.json` and is never sent again. A refusal says what happened and whether sending the same draft again can help: 400 malformed (no), 401 "the key or email was not accepted" (the server answers the same whatever did not match; no), 413 too large (no), 429 too many (later), 503 unavailable (later); no answer or another 5xx: it may or may not have been opened, so check for the new-ticket email first. Nothing retries by itself. Refuses a draft whose content no longer matches its id or carries unknown fields, a draft already sent or being sent, a key that is not a Pulsed Media `vsk-` key, and an address that is not https; a bundle draft whose files are not what `bundle` makes. An agent bundle goes out without asking only while `ticket.auto` is on (unset: on on a Pulsed Media server, off elsewhere), when it was bundled with `ticket.auto` already on (scrubbed, its message saying the holder has not seen it), collected without root for this account only, its files pass the automatic-ticket check, and Pikkumies is not running as root: at most 2 such attempts in 24 hours (sent, or failed with no answer, 429 or 5xx, or cut off mid-send) and never the same subject twice in 24 hours, under one lock; each attempt is written to `local/state/ticket/auto.jsonl` before it is posted (status -2) and again with the answer, and a ticket whose attempt cannot be written is not sent; the record says `auto`. A plain draft whose files carry the bundle's three names is refused. |
| list | | no | The drafts kept here, newest first: `id`, `made` (UTC), `subject`, `files`, `sent`. |

```sh
php ~/pikkumies/pikkumies/tools/system/ticket/ticket.php draft --subject "rTorrent stops overnight" --text "Since Monday rTorrent stops around 3am; restarting it helps until the next night." --email you@example.com
php ~/pikkumies/pikkumies/tools/system/ticket/ticket.php draft --subject "Web UI login fails" --text-file ~/ticket.txt --priority High ~/rtorrent-error.log
php ~/pikkumies/pikkumies/tools/system/ticket/ticket.php bundle --subject "rtorrent will not start after the disk filled" --diagnosis-file /tmp/x/diagnosis.md --review-file /tmp/x/review.md --log ~/rtorrent-error.log
php ~/pikkumies/pikkumies/tools/system/ticket/ticket.php bundle --by user --subject "Please check my server's network" --diagnosis-file /tmp/x/diagnosis.md
php ~/pikkumies/pikkumies/tools/system/ticket/ticket.php list
php ~/pikkumies/pikkumies/tools/system/ticket/ticket.php send 0123456789abcdef0123456789abcdef
php /home/USER/pikkumies/pikkumies/tools/system/ticket/ticket.php send 0123456789abcdef0123456789abcdef
```

- The send path must be absolute (as in the last line, with your own home directory) or start with `~/`, and point at this Pikkumies' own tool with no symlink in it; any other form is blocked.
- With approvals off (`HERMES_YOLO_MODE`, set by `--yolo`) or at `PIKKUMIES_DEPTH` 2 or more, the agent's `send` is blocked: the user's words cannot be checked there. The agent reports it as skipped and keeps the draft. A question that would not fit what the ask review can show in full (a very long email or file names) is blocked the same way.
- A ticket opened this way carries no authority for account changes: for a cancellation, refund, transfer, or a change of the account email or owner, support asks for a client-area login.
- Drafts stay until you remove them (`rm ~/pikkumies/local/state/ticket/<id>.json`). The remembered email: `~/pikkumies/local/state/ticket/email`; pass `--email` again to change it.
- A bundle's diagnosis file is Markdown with `## Problem`, `## Error`, `## Impact`, `## Tried` and `## Roadblocks`; each roadblock is a bullet `- <kind>: <why you could not do it>`, the kind one of `root`, `console`, `fleet`, `billing`, `platform`, `code`, `memory`. Other sections (`## Searched`, `## Next step`) are kept in the attachment.
- A bundle sends this server's name, addresses and process list to Pulsed Media over HTTPS, unsealed; as root or with sudo (off a Pulsed Media server, and never for an automatic ticket) the process list covers every account on the server.

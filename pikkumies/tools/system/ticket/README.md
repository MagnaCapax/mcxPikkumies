# ticket

Opens a Pulsed Media support ticket from inside Pikkumies, with your Pulsed Media AI key, so you do not need to log in to the client area for a question about your service.

You type `/ticket` and say what is wrong. The agent writes a subject and a message in your words, and shows you the draft: where it goes, the account email, the subject, how the message starts, the service, the priority and any files you named to attach, with their sizes. Common password and key forms are removed from the subject, the message and attached text and log files before the draft is saved; that catches the usual forms, not every secret, so read the draft before sending it. Images and PDFs are sent as they are. Nothing else is attached: no conversation, no system information.

The ticket needs the email of your Pulsed Media account (the owner's, or a user's who may open tickets) next to the key. The agent says once that it needs it, and remembers it in `~/pikkumies/local/state/ticket/email` once you give it. On a Pulsed Media seedbox the ticket names this account's service; elsewhere you can name the service or leave it out.

It is sent when you asked for a ticket: the safety check reviews the send against your own words ([ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md)), and the answer shows where it went, from which email, for which service, with which files, and how the text starts. You get the ticket number back, and your account gets the usual new-ticket email. A sent draft is kept, marked sent, and never sent twice. If sending fails, the draft stays and the error says whether trying again later can help. When the key or the email is not accepted, the answer is the same whichever it was, so check both.

With approvals turned off (`pikkumies run --yolo`), or in an agent started by another agent, the agent cannot send a ticket: your words cannot be checked there. It says so and keeps the draft.

The check before sending catches the agent's own and casual sends. It is a safety prompt, not a security boundary: an agent steered by text it reads could still post a ticket some other way, as it could run curl.

A ticket opened this way carries no authority for account changes: for a cancellation, refund, transfer, or a change of the account email or owner, support asks you to log in to the client area. It needs a Pulsed Media AI key (`~/.virsilipasKey`). Pulsed Media limits tickets opened this way per account and per hour; when a limit is reached, the tool says to try again later. Decision and options turned down: [ADR-0089](../../../../docs/adr/0089-support-tickets-with-the-ai-key.md).

## When Pikkumies is stuck: a ticket with the diagnostics attached

`ticket bundle` opens a ticket that carries what support would otherwise ask for over several replies. The short message gives the problem, the exact error, what was tried, and why Pikkumies could not finish it. For each roadblock it says what Väinämöinen, Pulsed Media's own support agent, has that this account does not: root on the server itself, the server's console even when it will not boot, a view of the other servers and of past incidents across all customers, changes to the account and billing record, platform updates and account moves, fixes in Pulsed Media's product code. Three files go with it: system facts, processes and logs; the agent's diagnosis, its ten-round review and every place it searched with the keywords and what matched; the conversation with its tool calls. When Pikkumies decides to ask is in [the ask-vainamoinen-for-help SOP](../../../doctrine/SOP/ask-vainamoinen-for-help.md).

What stays out: files in dot directories (`~/.ssh`, `~/.config`, `~/.pgpass`) and Pikkumies' own settings are never attached. The process list and logs cover only your account, unless Pikkumies runs as root or has passwordless sudo and you asked for the ticket off a Pulsed Media server. Common password and key forms are removed from all of it, as from any attached text file.

**Who sends it.** On a Pulsed Media server, a ticket Pikkumies bundles by itself goes out automatically, because the server is Pulsed Media's own. Turn that off at any time with the pikkumies-configure skill (`ticket.auto off`). Elsewhere it is off unless you turn it on yourself in `~/pikkumies/local/config.php`. Such a ticket also loses every long key-like string from its system and transcript files, since nobody reads it first, and it says that you have not seen it and that it authorizes no change to access, keys, passwords, firewall or files. A ticket bundled while automatic sending was off, or collected with root, or bundled while Pikkumies runs as root, always asks you first. Pikkumies opens at most 2 tickets by itself in 24 hours and never the same subject twice in 24 hours. A ticket you ask for always waits for your yes. Decision: [ADR-0100](../../../../docs/adr/0100-ticket-bundle-diagnostics-and-automatic-tickets-on-pulsed-media-servers.md).

# feedback

Sends Pulsed Media feedback from inside Pikkumies: what you say, plus the conversation you were having with the agent, so the problem can be seen as it happened.

You type `/feedback` and say what went wrong or what you want. The agent writes a draft and shows you its size, which session is attached and how the text starts. Common password and key forms are removed from the text and the conversation before the draft is saved; that catches the usual forms, not every secret, so read the draft before sending it. Besides your text and the conversation, the draft carries the Pikkumies, Hermes and PMSS version numbers, and the conversation carries the session's model, provider and working directory. It is sent when you asked for it: the safety check reviews the send against your own words ([ADR-0101](../../../../docs/adr/0101-refuse-and-report-never-ask.md)). What the check reads opens with where it goes and what goes: your text, the conversation transcript (all of it, or its newest 1.5 MB when it was cut to fit) and system information, to Pulsed Media at pikkumies.mcx.fi; then the size, the file holding all of it, and how your text starts. The message is locked on your machine with Pulsed Media's public key, so the server that receives it cannot read it, and only Pulsed Media can; it is linked to your Pulsed Media account through your AI key. A sent draft is kept, marked sent, and never sent twice. If sending fails, the draft stays and the error says whether trying again later can help.

In an agent started by another agent, the agent cannot send feedback: your words cannot be checked there. It says so and keeps the draft. Under `--yolo`, the default run mode, a send goes through the same check as any other.

The check before sending catches the agent's own and casual sends. It is a safety prompt, not a security boundary: an agent steered by text it reads could still run the sender some other way, as it could run curl. What it sends is sealed to Pulsed Media either way.

## Being asked now and then (off unless you turn it on)

Pikkumies can now and then ask, at the end of an answer, whether you want to send feedback about the session. It is off by default. At the first interactive start after this arrives it asks you once whether to turn it on (Enter means no, and it is never asked again); you can also ask the agent to turn it on. When it is on, Pikkumies asks only about a long session: at least 45 minutes since you started `pikkumies` and at least 500,000 tokens used in it (all requests, compactions included), in your own session on a terminal (not in scheduled jobs, chat gateways or agents started by agents; `--yolo`, the default run mode, makes no difference), and never twice in one session. There are two ways it asks, sharing one budget: in about 1 long session in 5 the agent ends an answer with the question, and otherwise, when you close Pikkumies, one line on the terminal asks how it did: `1 bad  2 fine  3 good  0 dismiss  n never ask`. A number sends Pulsed Media only that number, the session's length and token count (rounded to 5 minutes and 100,000 tokens), the model's name (never a file path) and the version numbers, sealed like `/feedback` and linked to your account through your AI key; no conversation. 0, Enter or 20 seconds without an answer send nothing, and `n` turns the questions off. After a question, the next one comes no sooner than 14 days later, or 30 days after a dismissed rating. These numbers are starting values. The question in an answer sends nothing: a yes starts the steps above, and the send is still checked first. The rating needs the same AI key and sodium; without them it is never shown. Say "never ask again", or use the pikkumies-configure skill, to turn it off (`feedback.ask`). A question in an answer adds about 70 tokens to that turn, on your credits; the rating at exit costs none ([hook](../../../hooks/system/feedback-ask/)).

It needs a Pulsed Media AI key (`~/.virsilipasKey`) and PHP with sodium. Hermes' own `/debug` is different: it uploads to a public paste site. For anything private, use `/feedback`, or `/debug local` to see the report without uploading it.

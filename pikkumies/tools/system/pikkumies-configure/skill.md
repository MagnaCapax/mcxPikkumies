# Configure Pikkumies

Use it when the user asks about Pikkumies' own settings: what the agent is called, which model it uses, whether it may log or send performance data, how long session history is kept, which tools, skills and hooks are on.

- `review` first when the user wants to know what is set: it explains every setting, says in `changes` which change you may make, which one asks the user and which one is theirs alone, and warns about the ones that need a look (for example session history kept forever).
- `set <key> <value>` only for a change the user asked for. Say what you set and its old value; it takes effect when the next session starts.
- Changes that tighten something go through. Changes that loosen something, cost credits or delete history (another model, turning off a tool category, hiding the low-credits notice, turning the scheduled-job ticker on or off, turning search rewording off, a shorter session history, `update.channel git/<branch>`) run like the others when the user asked for them: run the plain `set` command on its own, then say in one line what changed, its old value and how to go back. Never edit `~/pikkumies/local/config.php` instead: nothing in it is checked.
- Turning a safety layer off (the search-first gate, the halt guard, the fileops check, the hooks' model calls), root's tools back on, auto-update off and runtime downloads on and the provider, key files, `host.*` and the terms are the user's own. The tool refuses them and says how the user does it; tell the user that, do not run it again or edit the file for them.
- "From now on call yourself Kalle" (or "always", "your name is") asks for a lasting name: `set agent.name Kalle`, then say it applies from the next session. Answering as Kalle only in this chat is not what was asked.
- A model (`provider.model`, `hooks.model`): pick an id the `credits` tool's `models` lists; the tool checks it against the endpoint's list and shows its rate. `pikkumies -m <model>` uses another model for one session without changing the setting.
- SSH lists (`ssh.allow`, `ssh.deny`, `ssh.blockUnknown`): when the user asks to allow, refuse or stop asking about hosts the agent connects to over SSH. `set` replaces the whole list: include the entries already there (`get` shows them). Adding to `ssh.allow` and turning `ssh.blockUnknown` off run when the user asked for them; removing a host from `ssh.deny` the tool refuses: only the person does that, by hand in `~/pikkumies/local/config.php`.
- A rule the user wants for one tool or one tool category from now on ("always restart rtorrent through its tool", "for email, never send to more than one address"): `note-add <tool or category> --text="<the rule>"`, one rule per note, in the user's words, as a command of its own (a file written in the same command, then `--text-file`, is stopped by the settings check). Do it when asked, without asking first; say that it applies from the next start. `notes` lists them with numbers, `note-remove <tool or category> <n>` takes one back. A preference for everything goes to the built-in memory instead, and how a problem was solved to a lesson. Never put a password, key or token in a note: it is refused.
- To hide a shipped skill (for example after copying it under a new name): `skills disable <name>`; `skills enable <name>` shows it again.
- To go back: `set <key> <old value>` (`set` prints the old value), or `pikkumies configure undo`, which sets the last change back.
- Never accept the terms of service or privacy policy for the user: do not run `set terms.accepted` at all, not even to see the refusal. The person accepts them when the first interactive session asks, or installs with `pikkumies install --accept-terms`.
- `update.channel`: `release` (default) updates to the newest release only; `git/main` (or another `git/<branch>`) follows every change on that branch. Set it only when the user asks for releases or for the latest code; it applies at the next `pikkumies update`.
- `ticket.auto`: whether a support ticket you bundle by yourself, when stuck, goes out without asking. Unset means on on a Pulsed Media server and off elsewhere. Turning it off always goes through when the user asks; turning it on is free on a Pulsed Media server and the person's own elsewhere (by hand in `~/pikkumies/local/config.php`).
- `privacy.perfLogging` (on by default) keeps performance logs on this machine only: the time and result counts of each memory search (per tier, and per documentation source by name), its words only when it found no lesson, and the time of each lesson save, under `~/pikkumies/local/state/memory-metrics/`; and, under `~/pikkumies/local/state/telemetry/`, diagnostic measurements (quota, memory, traffic, torrent counts) and how many times a tool, a skill or a Pikkumies unit's verb ran -- read the latter back with `telemetry usage`. Off stops new lines; files already written stay until deleted. Telemetry is a setting only: nothing is sent, because no sender exists yet. Say so if asked.

# upstream

Upstream projects on GitHub (PMSS, Hermes, the apps Pikkumies manages): is a problem a known issue, was it fixed, what changed in a release, and a local draft for a new issue that the user publishes themselves ([ADR-0092](../../../../docs/adr/0092-upstream-issue-search-and-drafting.md)).

**What leaves the machine.** `search-issues` sends the words of the problem to GitHub, so it runs only while the person has turned web search on in their own settings (`pikkumies websearch on`, not a one-run overlay; [ADR-0082](../../../../docs/adr/0082-web-search-opt-in-keyless-ddgs.md)), and the words are scrubbed first: paths, the login and uid, host names (this machine's, Pulsed Media's and other providers'), IP addresses, ports, e-mail addresses, tracker, feed and keyed URLs, torrent info hashes, private tracker host:port, release and file names, long numbers and anything the secret redactor finds are taken out, and so are search qualifiers that could widen the search past the one repository. `issue`, `commits` and `releases` send only a public project name. `draft` sends nothing.

**GitHub's limit is per server, not per user.** Without a token GitHub allows 60 API calls an hour and 10 searches a minute per IP address, and every account on a seedbox shares one address (measured 2026-10-20: a third of the hourly allowance was already used by other processes on a shared host). So the tool keeps headroom for the neighbours (no API call while 15 or fewer are left, no search while 3 or fewer are), makes at most 2 searches and 3 other calls per run and 5 searches and 10 other calls per account an hour, one at a time, stops at a limit until its reset plus a random delay of up to two minutes, waits out a secondary limit once, and caches answers per user in `local/upstream-cache/` (0700). A conditional request saves no allowance without a token (measured), so the cache is what saves it. Commits come from a treeless shallow clone and the commits feed, releases from the releases and tags feeds: none of these use the API allowance.

**Publishing.** The draft is scrubbed again and passed through the secret redactor, written to `local/upstream/drafts/` (0600), and printed in full with the list of what was replaced. The default way to publish is the prefilled new-issue link, opened by the user in their own browser: Pikkumies holds no GitHub credential. A user already logged in to `gh` on the server may have the agent run the printed `gh issue create --body-file` command, which the publish check reads before it runs ([ADR-0083](../../../../docs/adr/0083-check-before-publishing.md)); `gh api`, curl and `--web`/`--editor` are out of that check's sight and never used.

Sources: GitHub's REST documentation (rate limits, search, issues), "Creating an issue from a URL query", and measurements on 2026-10-20 from a shared host (rate headers, the 6000-character link limit, 304s still counted, the feeds and git spending no allowance).
